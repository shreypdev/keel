# v1.x gap audit - what a real app team would hit, ranked

**Date:** 2026-10-01 · **Status:** discovery output for `.10x/specs/2026-10-01-v1x-default-choice-design.md` §1
(gap audit) · **Owner:** principal architect (worktree `wt/gaps`) · **ADR drafts:** ADR-034, ADR-035, ADR-036,
ADR-037 (all Proposed).

The bar is the founder's: *no engineer declines Undra because of something it cannot do; rock solid;
best-in-class DevX*. This document lists every gap the audit found in the code at `549b1f2`, each with
evidence (`path:line`, relative to the repository root), a severity and the piece of the v1.x plan that
closes it (track letters from the design doc; the new pieces A6 and A7 and the C4 split are proposed in §6).

**Severity.** *blocks adoption*: a team evaluating Undra would reasonably decline because of it (missing
capability, silent data loss, a crash class with no recovery). *hurts*: a team would ship but pay for it
(workarounds, a wrong-but-loud failure, a parity hole). *polish*: friction, drift or a missing nicety.

**Method.** Line-by-line reads of the cores (`undra-signals`, `undra-runtime`, `undra-query`, `undra-macros`,
`undra-bindgen`), the four core reviews' open findings, the SPEC and ADR-018…033; three parallel read-only
sweeps of the platform runtimes (port adapters, platform parity, dev loop + lazy lists) whose citations were
spot-checked; and throwaway probes in a scratch crate outside the repository (§7): 40 type-coverage cases
compiled one by one, the generated Swift / Kotlin / TypeScript of the supported subset compiled against the
real runtimes, and runtime probes for off-core writes (debug and release), a panicking computed, runtime
pinning, restore across a schema change and the cost of a derived list. Nothing in the repository was changed
besides these documents.

**Path shorthand.** Where a cell names a platform file without its full path: "Swift `X`" is under
`runtimes/swift/UndraRuntime/Sources/UndraRuntime/` (`Core/`, `Adapters/`, `Wire/`), "Kotlin `X`" under
`runtimes/kotlin/undra-runtime/runtime/src/main/kotlin/dev/undra/runtime/`, "TS `X`" under
`runtimes/ts/@undra/runtime/src/`; "golden" files are under `crates/undra-bindgen/tests/golden/full/`.

## 0. Summary

* **71 gaps: 7 block adoption, 40 hurt, 24 polish.** The blocking ones are concentrated in two places: the
  Android and web hosts (no Android storage/network/lifecycle adapters, no Android dev loop, a web core that
  dies from one storage error or panic with no recovery, worker mode that traps) and persisted state across
  an app update (offline queue deleted, snapshot restore silently misdecoded).
* **All four ADRs are needed** - none of the behaviours already holds:
  * ADR-034 (`WeakCtx`): every in-flight call and open stream holds a strong `Arc<Runtime>`
    (`crates/undra-runtime/src/runtime.rs:1271`, `:1317-1319`); a dropped-but-not-shut-down runtime with a
    task, subscriber, stream or `Ctx`-holding store is never freed (probe); Kotlin `close()` leaves the
    in-process core running.
  * ADR-035 (off-runtime writes): reproduced in a release build - a write from a thread with no runtime scope
    is accepted and never delivered; a write from a blocking-pool thread is delivered without the core lock.
  * ADR-036 (typed stream errors): flag 2 carries either `E` or a `String` and nothing says which; Kotlin and
    TypeScript decode the core's `"cancelled: …"` string as `E` and throw a wire error outside their error
    hierarchy.
  * ADR-037 (persisted-state migrations): the offline queue of the previous build is **deleted** on any
    schema change (`crates/undra-query/src/queue.rs:240-247`), the persisted cache is wiped, and a snapshot of
    the previous build **restores successfully with wrong values** (probe: `i32 -5` read back as `f32 NaN`, an
    enum variant shifted, `Ok(())`).
* **Two new pieces and one split are proposed** (§6): A6 web-core crash recovery, A7 storage ports with an
  error channel (plus worker-mode sync ports), and C4 split into C4a adapters / C4b failure model / C4c snapshot
  parity because it is the biggest piece in the plan. A3 (per-signal isolation) should be recorded as an
  ADR-019 amendment before code.
* **Verified clean:** `unsafe` is confined to `undra-ffi` and the CLI's schema loader
  (`crates/undra-cli/src/schema.rs:13`), every other library crate has `#![forbid(unsafe_code)]`, and no library
  crate prints. Constitution R2 holds.

## 1. Top ten by adoption risk

1. **Android ships without Http, Kv, SecureStore, Fs, Connectivity or Lifecycle adapters** (PO-1, blocks).
   `UndraCore.load` on Android installs Clock, Rng, Log and Timer only; `android-adapters` contains a frame
   pacer. Every Android team writes its own storage and networking before "hello world" talks to a server.
2. **An app update loses or corrupts the user's persisted state** (PS-1, PS-3, PS-2; blocks). Queued offline
   writes are deleted, the cache is wiped by any API change, and a snapshot restores into a changed store by
   position with wrong values and no error. Offline-first is the headline use of the data layer.
3. **One storage error or panic kills a web core, and nothing restarts it** (PC-2, PO-3; blocks). Kv and
   SecureStore have no error channel, so an unbound Kv (Node), an IndexedDB quota error or a missing
   `crypto.subtle` becomes a proxy panic, and `panic=abort` traps the module; `undra-query`'s persist writes hit
   that path unguarded. There is no restart-from-snapshot despite SPEC §7's sentence.
4. **Android has no `undra dev`** (DV-1, blocks; B1 in flight). The Kotlin remote transport is JDK-only.
5. **Kotlin's failure model crashes apps** (PA-2, PA-1, PA-3; hurts, near-blocking). A generated sync command
   throws a raw `UndraReplyException` into a Compose `onClick`; there is no `onError`, no closed taxonomy, and
   wire errors escape `UndraException`. Swift solved this in ADR-032; Kotlin and TypeScript did not follow.
6. **`wasm-worker` mode traps on the first clock read** (PO-4, blocks for that mode). The worker answers every
   port call "async", so the built-in Clock/Rng/Log are never reached and the infallible proxy panics;
   `undra-query` reads the clock on every observe.
7. **Stream failures are ambiguous on the wire** (SE-1, SE-2; hurts). The same flag carries a typed `E` or a
   cancellation/panic string; two of three runtimes misread it.
8. **Off-runtime writes vanish in release** (OW-1, OW-2; hurts). Silent drop under `undra dev`, an unordered
   delivery in production, and a misroute between runtimes - the opposite of "rock solid".
9. **Ordinary Rust domain models do not cross** (TY-1…TY-6; hurts). Newtypes, `Page<T>`, decimals/money,
   `uuid`/`chrono` types and factory methods returning objects are rejected; a linked record
   (`Option<Box<Self>>`) passes the macro and bindgen and then fails to compile in Swift.
10. **Large lists are not first-class** (RX-1, RX-2; hurts). A one-row edit in a 10,000-row keyed list ships
    39 bytes for the list and **192,647 bytes** for the filtered `Computed` view (145.5 µs core time); lazy lists
    exist in the runtime but are unreachable from app code.

## 3. Proposals, one per gap

**TY-1.** Bindgen computes, per record and enum, whether its type closure reaches itself through anything
but `Vec`/`Map` (direct, `Option`, or another record). Such a field is stored behind a generated indirection
(a private `final class` box holding the value, exposed through a public computed property), so the public shape
stays `public var next: ListNode?` and value semantics hold (the setter replaces the box). Mutual
recursion between enums gets `indirect` on every enum of the cycle. Golden case `recursive` with the linked
record, mutual records and mutual enums, compiled by the Swift golden typecheck. No schema change.

**TY-2.** Accept `#[undra::api] struct UserId(pub Uuid);` (one unnamed field) as a *transparent newtype*:
wire = the inner type's encoding; schema = a `RecordDef` with `transparent: true` and one field named `value`
(written only when true, like `no_coalesce`, so existing hashes do not move); platforms emit Swift
`public struct UserId: RawRepresentable, Hashable, Sendable, Codable`, Kotlin `@JvmInline value class UserId(val
value: UUID)`, TS a branded type `string & { readonly __brand: "UserId" }` with a constructor function. Needs an
ADR (generated public shape).

**TY-3.** Monomorphised aliases: `#[undra::api] pub struct Page<T> { .. }` is allowed when it carries
`#[undra(generic)]`, registers nothing itself, and each `#[undra::api] pub type TodoPage = Page<Todo>;` registers
a record `TodoPage` with substituted fields (the macro sees the alias and the template through a hidden
`macro_rules!` the generic expansion emits). Platforms see plain records; E0002 stays for un-aliased generics,
with the alias in its help text. Needs an ADR.

**TY-4.** Add `TypeRef::Object(name)`: an object crosses as its `u64` handle, owned by the receiver (the
platform wraps it in the generated class and releases it with `close`/finalizers, as for constructors). Lets
`account.mailbox(id) -> Mailbox` and `Option<Child>` cross. Schema and wire change (R1/R7) → ADR; the object
table and `release` semantics already exist.

**TY-5.** Add `TypeRef::Decimal`: encoded as `i128` mantissa little-endian + `u8` scale (17 bytes, exact),
mapped to Foundation `Decimal` (Swift), `java.math.BigDecimal` (Kotlin), and a small immutable `Decimal` class
with `toString`/`fromString` in `@undra/runtime` (TS); Rust side `undra_wire::Decimal` plus a
`rust_decimal` feature. Keep `i128`/`u128` as E0001 with the help pointing at `Decimal`. ADR (new wire type).

**TY-6.** Optional `undra-wire` features `uuid`, `chrono`, `time`, `rust_decimal`, `bytes` implementing
`Encode`/`Decode` for those crates' types onto the existing wire types (`uuid::Uuid` → Uuid, `DateTime<Utc>` and
`OffsetDateTime` → Timestamp with documented millisecond truncation, `rust_decimal::Decimal` → TY-5,
`bytes::Bytes` → Bytes); the macro's leaf table and the E0060 identity check accept these paths when the
feature is on. Each feature is checked on wasm32/iOS/Android before it lands (CLAUDE.md dependency rule). D1
collapses the 6-error cascade for a non-Undra type into one E0001 that names the feature to enable.

**TY-7.** Allow unit-only enums (u16 index) as map keys; bindgen maps them to Swift dictionary keys (the enum is
`Hashable`), Kotlin `Map<Filter, V>`, TS `Map<Filter, V>` (string literals). Records stay E0006 (no portable
hash/equality contract). Golden and contract vector for map-key ordering by encoded bytes.

**TY-8.** Keep the teaching error (tuples have no names on the platforms) and make SPEC 3.9's sentence say the
wire impls are for internal payloads, so readers do not expect tuple support.

**TY-9.** Kotlin bindgen overrides `equals`/`hashCode` whenever a field's type *contains* `Bytes` anywhere, and
emits deep-content helpers (`undraContentEquals(List<ByteArray?>…)`) in the runtime; alternatively map `Bytes` to
an immutable `UndraBytes` value class with content equality everywhere (preferred: it also fixes
`StateFlow` conflation and `Set` membership). Golden case with nested bytes.

**TY-10.** Native-review pass (R3) on leaf mappings, done once in C3 with the goldens: Swift `Bytes` → `Data`;
Kotlin `Vec<u8>` → `UByteArray` or a teaching nudge to `Bytes`; Kotlin `Timestamp` → `kotlinx.datetime.Instant`
is a dependency question (runtime is stdlib + coroutines only), so keep the runtime class but give it
`toInstant()`/`fromInstant()` on JVM; TS keep `bigint` but make `#[undra(js_number)]` discoverable from the error
a `JSON.stringify` user hits (docs + cookbook).

**TY-11.** `Duration` beyond `i64::MAX` ns encodes as `i64::MAX` *and* debug-asserts; document it as the
"infinite" value on every platform. A microsecond `Timestamp` is not worth a second time type in v1.x; document
the millisecond precision on `Timestamp` and in the cookbook.

**TY-12.** Writers enforce the same `MAX_DEPTH` (an encode past 128 levels is a panic with a teaching message
in debug and a typed `BadRequest` from the dispatcher in release), and the three platform decoders get the same
128 limit and a `nesting_too_deep` error, with a shared contract vector.

**TY-13.** The `CtxPorts` extension trait in `undra-ports` gains `ctx.new_uuid_v4()`, `ctx.new_uuid_v7()` (Rng
and Clock ports) and `ctx.now()` (a `Timestamp`); `undra-query` uses them instead of its private generator; the
template and playground stop hand-building ids.

**TY-14.** ADR-036 §4: the macro accepts `impl Stream<Item = Result<T, E>>` (and inside `Result<.., E>` with
the same `E`), records it in the schema exactly as `Result<Stream<T>, E>` (no schema shape change), and an
`Err(e)` item ends the stream with flag 2 carrying `e`. Platforms already throw `E` from such streams.

**PO-1.** Build `android-adapters` for real (C4a): Http over `HttpURLConnection` with OkHttp picked up
reflectively when present; Kv as files under `Context.filesDir` (same key scheme as `FileKv`); SecureStore as
AES-GCM files with a Keystore-held key (no deprecated `security-crypto`); Fs under `filesDir`; Connectivity over
`ConnectivityManager.NetworkCallback`; Lifecycle over `ProcessLifecycleOwner`; Log over `android.util.Log`. An
`AndroidAdapters.install(context)` (or a `ContentProvider` initializer) wires them so `UndraCore.load` needs no
adapter code, and the template and the playground use them (closes PO-13 for Android). Instrumented tests on
the `undra` AVD in CI.

**PO-2.** Node adapters in `@undra/runtime/node` (the export already exists): Kv/SecureStore as files under a
configurable directory (SecureStore AES-GCM with a key from the environment or OS keychain when available, else
refuse), Fs over `node:fs/promises`; `UndraCore.load` picks them when `process.versions.node` is set.

**PO-3.** A7: give `Kv` and `SecureStore` an error channel - `Result<Option<Bytes>, StorageError>`,
`Result<(), StorageError>`, `Result<Vec<String>, StorageError>` with `StorageError { Unavailable, Full, Locked,
Io(String) }` and `From<PortError>` (ADR-025's pattern). A standard-port signature change is a schema and
generated-shape change → ADR (amends ADR-024/025); nothing is published, so no compatibility path. `undra-query`
treats storage failures as "not persisted" (logged, counted) instead of panicking. Adapters map quota/lock/
missing-key failures to `StorageError` instead of throwing (today a throw becomes "unavailable" and a panic).

**PO-4.** Worker mode answers the sync ports inside the worker: the worker registers the built-in Clock/Rng/Log
answers itself (return 2 so `builtin::answer` runs, or answer synchronously from the worker's own clock and
crypto), and only async ports cross to the main thread. A contract scenario runs the playground core in
`wasm-worker` mode with a query observed. Together with A7 no remaining standard sync port can trap.

**PO-5.** Implement SPEC 5.2's "port cancel notification": a host-facing cancel (`port_cancel(port_call_id)`
callback / a `PortCancel` envelope kind) that the runtimes route to the adapter (`URLSessionTask.cancel()`,
`Call.cancel()`, `AbortController.abort()`); the abandoned-id cap stays as the backstop. ABI addition → ADR
(the C ABI grows by one callback, so it is decided against "the C ABI stays at 19 functions").

**PO-6.** Http v2 with streaming bodies is a port-design question for G2 (bidirectional streams); in v1.1 add a
`max_body_bytes` to `HttpRequest` handling (default 32 MiB, enforced by every adapter with a typed
`HttpError::TooLarge`) so a large download cannot exhaust memory. `TooLarge` changes a standard type, so it rides
on A7's ADR (standard port signatures).

**PO-7.** One definition: `timeout_ms` caps the whole exchange; no `timeout_ms` means a 60 s default on every
platform; adapters tested against the same fake server cases.

**PO-8.** One Fs contract in SPEC 8 (non-recursive delete of files, a separate `delete_dir`; paths are relative,
no `..`, no symlink escape; writes are atomic via temp + rename / OPFS `abort()` on failure) and a shared adapter
test suite run by all three runtimes. `delete_dir` is a standard-port change and rides on A7's ADR.

**PO-9.** Wire Lifecycle and Connectivity by default: Swift observes `UIApplication`/`NSApplication`
notifications (no SwiftUI dependency) and keeps `scenePhase` as an optional refinement; Android via PO-1; the
browser reports `inactive` on `pagehide`/`freeze`; the JVM keeps stubs. A contract scenario: background →
foreground triggers a stale refetch on every platform.

**PO-10.** JVM SecureStore encrypts with a key in the OS keychain where available (macOS Keychain via
`security`, Windows DPAPI, libsecret) and otherwise refuses to register (an explicit opt-in for plaintext);
Swift uses `kSecUseDataProtectionKeychain` on macOS and gets a Keychain test on a simulator; the browser
documents the secure-context requirement in the error SecureStore returns once A7 lands.

**PO-11.** A7 again: Rng gets no error channel (randomness must not fail), so the hosts must fail loudly
instead - the `random` import traps with a FATAL log when no CSPRNG exists rather than returning zeros, and
`new_uuid` panics (contained) rather than inventing a constant idempotency key.

**PO-12.** Kotlin `LoadOptions.logLevel` (default info, debug in debug builds) passed in `RuntimeConfig`;
Android logs through `android.util.Log`; core records go to the registered Log port when there is one (Swift and
TS already do).

**PO-13.** Playgrounds use the default adapters and point Http at the demo server by URL, not by a custom port;
the in-memory Kv stays only in tests. CI builds and tests `android-adapters`.

**PO-14.** G2/G3 as planned, gated on the founder's yes; the gap is recorded so the limitations matrix says
"planned" rather than nothing.

**PA-1.** C4b: Kotlin `LoadOptions.onError: ((UndraUnhandledError) -> Unit)?` and a public `UndraCore.report`,
called by generated commands, store `apply` failures, malformed change-sets and failed ports - the same
operations and wording as Swift's (ADR-032).

**PA-2.** Kotlin generated commands (a sync method returning `Unit` with no `E`) catch and `report` instead of
throwing, exactly like Swift; methods with a value or an `E` keep throwing.

**PA-3.** An ADR-032 analogue for Kotlin and TS: `UndraCallException` (sealed: `CancelledByCore`, `Panicked`,
`Refused`, `Unavailable(reason)`, `Malformed`) and `UndraCallError` (TS, `kind` discriminant) produced by one

other two runtimes).

**PA-4.** TS commands stay Promises (all TS calls are) but the generated command attaches a rejection handler
that reports to `onError` with the operation name when nobody awaits it (a `.catch` that rethrows to awaiting
callers); `onError` receives `UndraUnhandledError { operation, error }`; generated methods, constructors and

**PA-5.** TS `UndraCore.snapshot(): Promise<Uint8Array>` and `restore(bytes): Promise<void>` over the wasm

**PA-6.** ADR-034 §8: Kotlin `close()` of an in-process core calls the native shutdown (a new JNI native: the

**PA-7.** Part of B2: a connection state (`connecting`, `connected`, `reconnecting(attempt)`, `closed(error)`)
observable on all three runtimes (`AsyncStream`/`StateFlow`/`subscribe`), a dead remote core stops being

**PA-8.** C4b normalises: `stats()` synchronous where the data is local (TS keeps a Promise only for the core

**PA-9.** Update SPEC §17 to the shipped shapes (or the code to the SPEC where the SPEC is right); route
malformed change-sets and failed ports to the unhandled-error hook on all three runtimes.

**DV-1.** B1 (in flight): an OkHttp-or-`java.net.Socket` WebSocket client usable on Android, `LoadOptions(mode =
REMOTE, remoteUrl)` on Android, the emulator's `10.0.2.2` default, and a debug-only dev hook in the template.

**DV-2.** B2 (in flight): reconnect with jittered backoff, Hello again, refuse on a schema change with a typed
error, re-observe every mirrored `(handle, signal)`, fail in-flight calls with `unavailable(connectionLost)`, and
the status API of PA-7.

**DV-3.** B3: the runner takes a control command (stdin line `snapshot <path>`) and writes `runtime.snapshot()`
before `server.shutdown()` (so `release_on_disconnect` cannot run first); the next runner restores it before it
listens; clients reconnect (B2), re-observe, and keep their handles because restore re-issues them (ADR-022).

**DV-4.** With DV-3's runner-side route no wire change is needed for B3. A client-initiated snapshot (for
devtools time-travel, B4) needs a request kind → decide it in B4's ADR, not now.

**DV-5.** `undra dev` compares the new schema hash with the old one; on a change it regenerates bindings (the

**DV-6.** Log Rust-bound and sync port calls in dev mode with timing; the inspector is B4.

**DV-7.** H1 adds the dev loop to `docs/ONBOARDING.md` and the cookbook, per platform, after B1/B2.

### 4.4 Dev loop

`undra dev` debounces 300 ms, rebuilds, stops the old runner and starts a new one on the same address
(`crates/undra-cli/src/commands/dev.rs:76-101`). Nothing is snapshotted; the transport closes the client with
1001 and releases its stores (`crates/undra-transport/src/server.rs:197,382`; `session.rs:297-339`); a client
with the old hash is refused with 1008 (`session.rs:157-174`). No runtime reconnects (DV-2); Android has no
remote mode (DV-1). **What B3 needs:** a runner control command to snapshot before shutdown, restore before
listen, client reconnect + re-observe (B2), ownership of restored handles recorded for the reconnecting session
(otherwise `release_on_disconnect` leaks them), ADR-037 identity so a changed store is migrated or refused
instead of misdecoded, a policy for non-store objects (query handles and lazy lists come back stale today, so
the platforms would have to re-create query handles on `stale_handle`), and "regenerate bindings" when the hash
changes (DV-5).
Devtools records exist (`runtime.rs:849-863`) but not for Rust-bound or sync ports.

### 4.5 Reactivity

`Effect` is in the prelude (`crates/undra/src/lib.rs:47`) with good rustdoc and unit tests, one runtime
integration test (round cap), no playground use; footguns RX-3/RX-4. Lazy lists: RX-2. Derived keyed lists: a
`Computed<Vec<T>>` always ships op 0 (full value); measured in §7: 192,647 bytes and 145.5 µs per one-row edit
at 10,000 rows (6,667 visible), against 39 bytes for the keyed source.

### 4.6 Persistence across schema changes - decides ADR-037

| Artefact | On a schema-hash change today | Severity |
|---|---|---|
| Offline queue (`undra.query.queue`) | deleted on load, WARN "dropping a persisted offline queue from another build" (`queue.rs:240-247`) | silent data loss → blocks |
| Persisted query cache | each entry deleted on load, DEBUG log (`shared.rs:845-857`); whole-schema hash | hurts |
| Snapshot (`undra_snapshot`/`restore`) | **no identity check**: signals restored by position with the new types; a missing signal or unknown store type fails the whole restore, a compatible-width type change succeeds with wrong values (probe) | silent corruption → blocks |

ADR-037 is therefore needed; ADR-022's floor and ADR-023's all-or-nothing restore stay.

### 4.7 Lifecycle

What pins a runtime (probe, threaded `Runtime::new`, owner `Arc` dropped without `shutdown`): an open stream or
in-flight async call (the runtime's own tasks hold `Arc<Runtime>`, LC-1); a spawned task that keeps a `Ctx`
(alive after drop); an event subscriber that captures a `Ctx` (alive after drop); a store that keeps a `Ctx`
(object table → store → `Ctx` → runtime); `undra-query`'s hydration (6–8 s) and GC tasks (up to 5 min). An idle
runtime is freed after the hydration window. `shutdown` breaks every cycle (ADR-023), so embedders that call it
are fine; what users see today: Kotlin `close()` leaves the in-process core running and refuses a reload
(PA-6); a thread outside the runtime that keeps a `Ctx` after shutdown gets WARN no-ops and an immediately
completing `sleep` (a polling loop there spins) with no typed signal to stop; a dropped `Runtime::new` leaks its
core, timer and pool threads. Shutdown order (`runtime.rs:576-624`): refuse new tasks → answer calls/streams
(status 3 / flag 2) under the core lock → join core thread → stop timers and pool → cancel port calls → clear
subscribers and Rust bindings → drop tasks and objects under the core lock → release the global slot.

### 4.8 Off-runtime writes

Debug: the checker (`crates/undra-signals/src/context.rs:56-74`, an allowlist: core-lock holder, test driver,
`unchecked_writes`; `runtime.rs:173-181`) panics. Release: never evaluated. Probe (release): a write from a
plain thread on a `Runtime::new` runtime is applied and never delivered (change-sets 1 → 1; the core and host
disagree until the signal is written again or re-observed); from a blocking-pool thread it is delivered without
the core lock (1 → 2). On the global runtime (the FFI) the plain-thread write reaches the host, so `undra dev`
(non-global) and production (global) behave differently. ADR-035 is needed.

### 4.9 Panicking computed

Native: the panic is caught inside the commit (`txn.rs:301-323`), the store's claimed slots are marked unsent
(ADR-019) and the first panic is re-raised into the writer (`txn.rs:242-245`). Every signal of that store is
held back, every write to it fails (status 2 for a call, the store marked poisoned), and other stores in the
same transaction are delivered; the runtime survives. Probe: five writes to an unrelated `title` → five panics,
zero change-sets; the next good write resends all three signals in full. wasm: `panic=abort` - the whole core
traps and the TS runtime marks it dead (PC-2).

### 4.10 Stream error items

Producers of flag 2: (1) a failed async opening of `Result<impl Stream, E>` → encoded `E`
(`crates/undra-macros/src/impl_/object.rs:869-873` → `runtime.rs:2372-2375`); (2) restore cancelling a call on a
replaced receiver and (3) shutdown → `String "cancelled: …"` (`runtime.rs:1424-1428`); (4) a stream task panic →
`String "the stream panicked: …"` (`runtime.rs:1758-1764`). Cases 2–4 happen for streams *with* an error type
too. Swift tries `E`, falls back to the string and matches the `"cancelled: "` prefix; Kotlin and TS decode `E`
only and throw a wire error (the string's length is read as a variant tag), and for streams without `E` hand
the consumer a raw "typed error" with the string unread. A synchronous `Result<impl Stream, E>` failure is a
reply status 1, not a stream item. ADR-036 is needed.

### 4.11 Anything else

`unsafe` and printing: clean (§0). Memory growth: persisted cache (PS-4); the keyed baseline is one clone per
observed keyed list (documented); the abandoned-port set is capped (ADR-023). Concurrency: computed closures
run under the delivery lock (RX-5); effects run on the committing thread (RX-4). Start-up: OT-5. `Send`/
`Sendable`: Swift port protocols are `Sendable`, generated objects `@unchecked Sendable` over immutable state;
no gap found. Docs that over-promise: OT-1.

## 5. What the ADRs decide (one line each)

* **ADR-034** - anything that outlives a call holds a `WeakCtx`; the runtime's own tasks and `undra-query`'s
  stop pinning it; subscribers receive the `Ctx`; `WeakCtx::upgrade() -> Result<Ctx, Gone>` and `Ctx::closed()`
  are the typed end; dropping the owner frees the runtime; Kotlin `close()` shuts the in-process core down.
* **ADR-035** - a signal write from a thread that does not hold the owning runtime's core lock is refused in
  every build (the teaching panic, or `WriteError` from `try_set`/`try_update`); change-sets are routed by the
  store's owner; `Ctx::with_core` is the sanctioned path for host threads.
* **ADR-036** - flag 2 carries only the stream's `E`; a new flag 3 carries `status, message, detail`;
  `impl Stream<Item = Result<T, E>>` ends a stream with a typed error. Pre-publication wire change.
* **ADR-037** - persisted artefacts carry a format header and per-item type fingerprints with an embedded type
  description; equal loads, different migrates structurally by name, then through an app `#[undra::migrate]`
  hook, and what still cannot load is refused (restore) or dead-lettered (queue), never dropped silently.

## 6. Changes to the plan

* **New A6 - web-core crash recovery** (PC-2), v1.1, `wt/web-recovery`, sonnet + opus review; needs PA-5 (TS
  snapshot/restore) and ADR-037 (a snapshot taken before an update must not misdecode after it).
* **New A7 - storage ports with an error channel; no standard port can trap** (PO-3, PO-4, PO-11), v1.1, joins
  `wt/runtime-lifecycle` or its own `wt/ports-typed`; needs an ADR amending ADR-024/025 (standard port
  signatures change; nothing published).
* **Split C4** into **C4a adapters** (PO-1, PO-2, PO-7…PO-10, PO-12, PO-13; Android work is the largest single
  item), **C4b failure model** (PA-1…PA-4, PA-8, PA-9: an ADR-032 analogue for Kotlin and TS) and **C4c snapshot
  parity** (PA-5). C4a should start in phase 1: it blocks Android adoption and needs no ADR.
* **A3 gets an ADR-019 amendment** before code (it changes when a store's change-sets are delivered); RX-3 and
  PC-3/PC-4 join it.
* **C3 needs ADRs** for TY-2 (newtypes), TY-3 (generic aliases), TY-4 (objects as values) and TY-5 (decimal);
  TY-1, TY-6, TY-7, TY-9…TY-13 need none. Suggested order: TY-1 and TY-9 (correctness) first, then TY-6/TY-13
  (interop, small), then the ADR-backed shapes.
* **PO-5 (port cancel) needs an ADR** that revisits "the C ABI stays at 19 functions": one more host callback.
* **Ship ADR-036 and ADR-037's snapshot layout in one wire revision**, before anything is published (the
  architect's earlier note said A4 is the last pre-publication wire change; ADR-037 also changes the opaque
  `Snapshot` payload, so they land together).
* **Sequencing.** Phase 1 adds C4a. Phase 2 orders Track A as: ADR-035 + ADR-036 (small, wire), ADR-034, then
  ADR-037 (largest), with A6/A7 after ADR-037 and PA-5.
