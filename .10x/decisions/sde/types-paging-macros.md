(hidden). `MapKey` is implemented for `String`, `bool`, the integers, `Uuid` and, behind `uuid`, `uuid::Uuid`, and by one

## Decisions where the brief or the ADR left a choice

1. **`MapKey` is a blanket over `Newtype`, not a per-newtype conditional impl.** `impl MapKey for UserId where Uuid: MapKey {}`
   is a trivially false/true where-clause on a concrete type: rustc rejects it at the definition when false (`struct
   Price(Decimal)` would not compile at all). The macro emits `impl Newtype for UserId { type Inner = Uuid; }` and one blanket
   `impl<T: Newtype> MapKey for T where T::Inner: MapKey` does the rest. `Newtype` carries the E0006 message too, because rustc
   reports the innermost failing bound (`Decimal: Newtype`), not `Price: MapKey`.
2. **The template's macro is re-exported under the type's own name, in the macro namespace** (`pub use
   __undra_template_Page as Page;`). A macro and a type do not collide, and `use model::Page;` imports both, which is how an
   alias in another module finds the template with no path of its own. (Verified: imported, renamed (`as Pager`), qualified,
   `crate::`, `super::`, root and nested modules; no `macro_expanded_macro_exports_accessed_by_absolute_paths` lint.)
3. **An instantiation checks only its type arguments.** A `macro_rules!` resolves names where it is *invoked*, so re-spelling
   the template's field types at the alias would need every type the template mentions (a `Cursor` imported only in `model`)
   to be in scope in the alias's module. The template checks its own types where they resolve (generic over its parameters,
   a position that is a parameter is skipped); the instance walks only the `None`-delimited groups the `$T:ty`
   metavariables leave, plus the map keys they make. `Self` in a template is `Page<T>` for the checks and the alias in the
   instance. Test: `tests/ui-runtime/newtypes_and_generics.rs`.
4. **E0070 for another crate** is detected by the macro itself: the template's `macro_rules!` embeds `CARGO_CRATE_NAME` of its
   expansion, `__instantiate!` compares it with its own (skipped when either is unknown, e.g. no cargo), so the message is
   branded and names both crates instead of `rustc`'s E0116. Verified once end to end with two scratch crates. The duplicate
   alias of one instantiation is `rustc`'s duplicate associated constant: the constant named after the rule comes first in the
   impl and is spanned at the alias, so it is the first error and points at both aliases (`tests/ui/e0070_second_alias`). The
   catalogue needs a branded message in a golden: `tests/golden/diagnostics/E0070.txt`, written by a unit test
   (`UPDATE_GOLDEN=1 cargo test -p undra-macros --lib`).
5. **The feature mirror.** A macro cannot ask whether `undra-wire` has `chrono`, so `undra-macros` has its own copy of each
   leaf feature (`uuid`, `chrono`, `time`, `rust_decimal`, `bytes`), turned on by `undra`'s. With the feature off a spelling
   only that crate has (`DateTime<Utc>`, `OffsetDateTime`, `UtcDateTime`, `TimeDelta`, and the crate-qualified
   `uuid::Uuid`, `rust_decimal::Decimal`, `bytes::Bytes`, `time::Duration`, `chrono::Duration`) is **one E0001** naming the
   feature (what ADR-042 4.3 says; the brief's "E0060's leaf text" is the membership message). A bare `Uuid`, `Decimal`,
   `Bytes` or `Duration` may be the built-in or the crate's type, so the spelling cannot say: without the feature that is the
   compiler's three errors (E0060 membership and the two codec bounds, every one naming the features), like D1's NF2 ("three
   errors that agree on the fix"). `tests/ui-leaf-off/` locks both, and runs only while no leaf feature is on. With the
   features on, `undra-macros --lib --features ..` runs the opposite cfg-gated tests. Users who name the crates directly with
   `crate = ".."` must enable the same features on `undra-macros` (the message says so).
6. **Generic newtypes and enums are supported** (`Tagged<T>(pub T)`, `Loadable<T, E>`): a generic newtype instantiates as a
   transparent record and is a key exactly when its argument is. A template cannot carry `#[undra::error]` (E0002, "remove the
   parameter and declare one concrete `#[undra::error]` enum").
7. **Template and alias rules added**: `generic` on an item without type parameters, or on anything but a struct or an enum, is
   E0008; a default type parameter is E0002; `T::Item` in a template is E0001; the wrong number of arguments is a branded E0002
   from a catch-all rule of the template's macro (next to `rustc`'s own E0107); `crate = ".."` on an alias is E0008 (the
   template's root is used, and the macro calls `<root>::__instantiate!`, so `crate = ".."` must reach a crate that re-exports
   it: the facade does); the alias's docs, else the template's, are the record's docs.
8. **`__UNDRA_FIELDS` of a newtype is empty**: `#[undra(key = "value")]` on a list of bare newtypes says the newtype has no
   fields (a keyed list's *key field* may be a newtype, which works with no `store.rs` change: the key function hashes the
   encoded field; `tests/newtypes_generics.rs::a_keyed_list_matches_its_items_by_a_newtype_key_field`).
9. **Syntactic E0006 stays for non-`Named` keys** (`f64`, `Decimal`, `Vec<..>`, `Option<..>`, `Duration`, `Timestamp`, `Bytes`);
   a `Named` key passes the mapper and the trait decides. A port parameter with a record key is therefore E0006 (the compiler's
   bound) rather than E0030.

## Not done, on purpose

* `docs/SPEC.md` 16.3 (what the macros emit) is not in the sections the brief names: it does not yet list `undra::__instantiate`,
  `leaf::{MapKey, Newtype, WireLeaf}`, `impl TodoPage`, the template's macro. The cookbook's "modelling your domain" page and the
  site's guides are the docs agent's.
* Private aliases and private records get `dead_code` / `unreachable_pub` on the generated `pub const`s under
  `#![deny(unused, unreachable_pub)]`: unchanged behaviour of every record, not a regression.
* A template declared inside a function body is not supported (`#[macro_export]` is module-level).
