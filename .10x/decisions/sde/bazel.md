## What a build does (the part worth reading)

`undra_core` runs `undra build --platform <p>` in an action: the `rules_rust` toolchain (exec platform + a split transition per target
platform, sysroots merged by `run.sh`, `rustc` wrapped to pass `--sysroot`), crates.io packages downloaded by the checksum
`Cargo.lock` records and unpacked into a Cargo directory source at `$CARGO_HOME/registry/src/index.crates.io-1949cf8c6b5b557f`,
`CARGO_NET_OFFLINE`, the Undra crates as `[patch.crates-io]` into a pruned copy of the checkout, the sources copied (never written
into), the scratch directory `/tmp/undra-bazel/<digest of the inputs>` behind a pid lock. `@undra//:cli` is `cargo build -p undra-cli`
the same way. `undra_bindings` runs `undra bindgen --library` on `core_host`'s library: no second compile.

## Findings

* **The CLI is not byte-reproducible across directories.** `undra build --platform web` of one core in three directories: three
  modules (274.6 KB within 0.1%). Cause: Cargo hashes a path dependency outside the workspace (the core, the Undra crates) by its
  absolute path into `-C metadata`; the mangled names differ; `wasm-opt` breaks ties between functions by name. `RemapRoots` (ADR-052)
  keeps path strings out of the binary and not this. A random scratch directory per action gave 274.1 to 275.1 KB over five runs; naming
  the directory by a digest of the inputs gave byte-identical modules and libraries across two clones (one by path, one from an archive,
  fresh output roots). The CLI fix (build the core from inside the shim's workspace) is a follow-up.
* **`ts_project` and `swift_library` do not take a directory**; `rules_kotlin` takes a `.srcjar`. The consequences are in the ADR.
* **ktlint, run from Bazel, reproduces the complaint and proves the fix.** `rules_kotlin` pins ktlint 1.8.0 (a public `java_binary`).
  Over the example's generated Kotlin: 90 findings with neither exclusion, 0 with either, 0 with both. It is a test now
  (`//kotlin:lint_test`; the four cases run on copies in the test's temp directory, so the negative case cannot pass vacuously).
* **`aspect_rules_js`/`aspect_rules_ts` pull in `aspect_tools_telemetry`** (reports the rulesets and versions a build uses to Aspect).
  The example sets `--repo_env=DO_NOT_TRACK=1`; the docs page, the example README and the ADR say so. The lead should decide whether
  the repository's own `.bazelrc` files keep it.
* **`apple_support` has to be first** among the root module's dependencies for `rules_swift` (its own `local` target triple
  otherwise); `rules_android_ndk`'s repository rule `fail`s with no NDK, so Android's C++ toolchain cannot be in a module every
  machine evaluates.
* `rules_rust` 0.74 knows compiler checksums up to 1.98; 1.99.0 is pinned in the application's `rust.toolchain(sha256s = ..)` from
  `static.rust-lang.org`'s `.sha256` files (the darwin ones agree with `rules_rust`'s own debug print).
* **`ci-local` found a regression the local test runs had not**: the ignored `schema_docs` test compares the bindings from the library's schema with
  those from the dev runner's, written to two differently named directories, and my first lint fragments named the directory. They no
  longer do (ADR note 10); the committed trees and goldens were regenerated again.
* A sandbox with the network off (`--sandbox_default_allow_network=false`) builds the cores and the bindings.

## Lint exclusions, and the other piece

`generated-weight` (ADR-062) owns `.gitattributes` (`linguist-generated=true`) and two JSON headers; this piece wrote only the lint
files and the Kotlin header, none of its files. Both change `plan_files` and every committed tree's `.undra-generated`: the merge is
mechanical: after it, regenerate each tree (`undra bindgen -C examples/<x> [--docs]`: cookbook, fieldbook, playground, two-cores a and
b with `--docs`; ios15-sample without) and the goldens (`UPDATE_GOLDEN=1 cargo test -p undra-bindgen --test golden`,
`UPDATE_GOLDEN=1 cargo test -p undra-cli --test bindgen_schema`). The lint code is in its own module (`lint.rs`) and one call in
`plan_files`, to keep the textual overlap to that line.
