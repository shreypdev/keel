# SDE - the envelope magic becomes UNDR (wt/magic, 2026-09-30)

Executes ADR-033. The only wire change before the first publication; the rename record
(`rename-undra.md`) listed it as the one place the old name survived. This record spells the old
bytes where it has to: `4B 45 45 4C` ("KEEL"), now `55 4E 44 52` ("UNDR").

Not touched on purpose: `.10x/reviews/`, ADR-018 to ADR-030, `rename-undra.md` (history);

"UNDRA_RNG", now says what the value is); `site/` (excluded from the rename; the figure on
`site/docs/architecture.html` still prints `KEEL` and needs `UNDR` when the site crosses).

## Goldens, schema hash

No golden embeds the magic (a grep of every golden for the bytes, the hex and the letters finds
nothing), so none was regenerated and `UPDATE_GOLDEN` / `UPDATE_SNAPSHOTS` / `TRYBUILD=overwrite`
leave the tree unchanged. The schema hash does not depend on the magic.

## The vector drift (the second commit)

`runtimes/swift/.../Resources/wire-vectors.json` lacked `map_key_order_by_encoded_bytes`, added to
the shared table in e7e4d99 without a sync, so `runtimes/swift/scripts/sync-vectors.sh --check` had
failed on `main` since then (found by the rename piece, left alone). Synced here; the Swift
`WireVectorTests` already understood the `map<string,i32>` type. CI now runs the check in the Rust
(Linux) job, because it is a plain `cmp` and needs no toolchain. The Kotlin counterpart
(`gen-vectors.py --check`) already ran inside `test-local.sh`.

One flake seen and not caused by this change: `undra-transport`'s `a_chatty_client_is_never_pinged`
(a 150 ms ping interval against a client sending every 50 ms) failed once in a full `cargo test
--workspace` that ran while `npm ci` / `npm test` shared the machine. It passes alone (three runs of
the whole `lifecycle` file) and in the unloaded full rerun above. Its failure output showed a
correct `55 4E 44 52` envelope. A timing-sensitive test is worth loosening or marking as needing a
quiet machine; left alone here.
