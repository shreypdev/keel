# SDE: the playground (branch `wt/playground`)

The reference app of Undra v1 (R10) and the subject of the SPEC 14 contract scenarios. Nothing in the
Undra crates changed; everything lives in `examples/playground/` and `contract-tests/`.

## What exists

| Piece | Where | State |
|---|---|---|
| Core (`playground-core`) | `examples/playground/core` | 47 unit tests on `TestRuntime` + `undra::ports::fakes`; clippy `-D warnings`, fmt, `cargo doc -D warnings`, `deny(missing_docs)`; builds for wasm32 |
| Project + bindings | `examples/playground/undra.toml`, `generated/` | written by `undra bindgen --docs`, `--check` passes |
| Contract scenarios | `contract-tests/scenarios.md`, `check.sh`, `run-all.sh` | 17 scenarios, 17/17 PASS on TypeScript (wasm), Kotlin (JNI), Swift (C ABI) |
| Web app | `examples/playground/web` | builds; Playwright smoke in headless Chromium passes (`.proof/web-*`) |
| iOS app | `examples/playground/ios` | builds for the iPhone 17 Pro simulator; `smoke.sh` launches every tab, XCUITest tour passes (`.proof/ios-*`) |
| Android app | `examples/playground/android` | `assembleDebug`; ran on the `undra` AVD, driven through uiautomator (`.proof/android-*`) |

## Decisions worth knowing

* **One core, three jobs.** Reference app, contract subject, benchmark target. The core is broad on
  purpose: todos, counter, 10k keyed list, remote query, `lab` (every wire type, sync/async, errors, panics,
  cancellation, streams), `bench`.
* **`Bench` is one store** with 128 `Signal<u32>` counters (signals 1..=128, generated by a
  `macro_rules!` that expands to `#[undra::store]` at item level: an attribute macro sees the expanded fields,
  but not struct literals hidden inside a macro call in an impl body) and a 10,000-row keyed list (signal 0).
  The budget rows are `bench_add`, `bench_echo_bytes(data)`, `bench_touch_signals(k)`, `bench_list_insert(i)`
  (+ `bench_list_reset`). `bench_echo_bytes` takes the payload (n = its length), it does not generate n bytes.
* **Remote lists are keyed by name** (`remote_todos(list)`, key `remote-todos:{list}`), so two lists are two
  cache entries and contract scenarios isolate themselves by list name on the one-core-per-process platforms.
  Bodies are JSON (serde_json, about 40 KB of wasm) because that is what real servers speak; the apps and the
  scenarios answer the `Http` port with an in-memory server.
* **S17 has two definitions.** Native platforms: the panic is a status-2 reply and the core lives on. wasm:
  the shipped profile aborts on panic (SPEC 7), so containment is: the call fails, a fatal log arrives, the core
  is closed, and a fresh instance restores the snapshot taken before.
* **Names that would collide in a UI module** are avoided on purpose (`Figure`, not `Shape`; `Item`, not `Row`):
  SwiftUI has `Shape`, Compose has `Row`.
* `undra build` for this project writes `examples/playground/target` (the CLI's target dir is
  `<project root>/target`), a second copy of the dependency build next to the workspace's `target/`.

## Findings for the integrator (repros: `contract-tests/*/NOTES.md`, `Findings.swift`, `test/findings.test.ts`)

Defects in merged crates and runtimes:

1. **undra-signals: a keyed patch is O(list), not O(change).** One insert into the observed 10,000-row list:
   about 471 us natively (release, in-process dispatch, `Bench.bench_list_insert`), 1.26 ms on wasm under node;
   4.4 us when nothing observes the store. Blueprint section 14 budget: 20 to 40 us. The time is the diff of
   old against new list (SPEC 3.8 "by key equality and full-item encoded equality"). The bench piece will fail
   this row until the cell can build the patch from the write instead of diffing.
2. **undra-query: a failed mutation's rollback removes a later mutation's optimistic placeholder** (it restores
   the entry as it was before the failed mutation ran). Repro: toggle (PATCH in flight), then add; the PATCH
   fails; the add's item vanishes (while offline and queued it stays gone until the replay).
3. **undra-bindgen (Swift): generated stream methods lose backpressure** (`undraDecodeStream` copies the
   runtime's pull-based stream into an unbounded `AsyncThrowingStream`): after reading 5 of 1,000 items the
   core produced all 1,000. Kotlin and TypeScript honour credit.
4. **UndraRuntime (Swift): `InprocTransport.start` calls `undra_init` before comparing schema hashes**; on a core
   that is already initialised, `load(wrong hash)` fails with `coreInitFailed`, not `UndraSchemaMismatchError`
   (SPEC 11 says the check is at attach).
5. **@undra/runtime Mirror strands a change-set enqueued from a signal subscriber** (`flush()` keeps
   `#flushing` set while `batch()` notifies): a synchronous core call made from a subscriber is not applied
   until an unrelated change-set arrives. Fix: re-check the queue after `#flushing` is cleared.
6. undra-bindgen (Swift 6.3): every generated store warns "must restate inherited '@unchecked Sendable'".

API gaps: TS `UndraCore` has no `snapshot()`/`restore()` and generated stores cannot adopt an existing handle
(after a restore in a fresh core); `@undra/runtime/react` does not exist (SPEC 10.3, 13); Swift's standard-port
records (`HttpRequest`, ...) are internal and not generated, so an app's own `Http` adapter writes their wire
layout by hand (ADR-024 open question); Kotlin `PortImpl` method maps need a public builder (Kotlin 2.0.21
infers non-suspend lambdas) and `UndraStats` lacks `crossings.*` and `schema_hash`; Android has no default
`Http`/`Kv` adapters (the android-adapters module is not built), so every app supplies its own.

Tooling: `scripts/env.sh` prefers `../.tools/rust/bin` (Linux ELF) and breaks cargo on this Mac; the host
dylib's install name is an absolute path into `target/`; `undra build --platform ios` prints Android SDK noise;
the template's jniLibs path is relative to `app/`; `undra build` defaults to debug (42 MB per ABI; the
playground APK is 96 MB debug, 13 MB with a release core); `generated/kotlin` gets Gradle output inside the
committed tree (ignored in `.gitignore`); a generated package dir named `swift` collides in SwiftPM with a
package in a directory called `swift` (the contract runner uses a committed symlink).

## Sizes (playground, not hello-world; the budgets are for hello-world)

wasm 538 KB / 205 KB gzip (of which serde_json about 40 KB); Android release core 1.5 MB arm64, 1.6 MB x86_64;
iOS release 7.8 MB per slice (app bundle 4.7 MB after strip); debug iOS xcframework 157 MB.

## Numbers measured on the way

Sync call (wasm-main, node) about 1.4 us; Swift C ABI sync call about 2.1 us through the generated binding;
web startup to interactive 48 ms; 10 updates/s streaming on the 10k list: 62 frames per second, longest gap
16.8 ms. `bench_touch_signals(100)` observed, core side only: 2.5 us.
