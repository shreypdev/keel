# SDE: the API reference on the site (wt/docs-reference, H3, 2026-10-01)

An exhaustive reference next to the narrative API pages, built from the code so it cannot drift: rustdoc for the Rust
side, and one page per platform for what `undra bindgen` emits. No code under `crates/`, no ADR, SPEC or schema change.

## What the pages show

* **Rust** (`/reference/rust/`, not committed): `cargo doc --no-deps` for `undra` and the six crates its facade
  re-exports (`undra-runtime`, `-signals`, `-query`, `-ports`, `-wire`, `-meta`). `examples/playground/core` imports
  `undra::prelude::*`, the attribute macros, `undra::ports::{HttpError, HttpRequest, ..., fakes}`,
  `undra::runtime::testing::TestRuntime` and `undra::signals::ALL_SIGNALS`; with `--no-deps -p undra` alone the facade's `pub use undra_runtime as runtime;` links go nowhere, so
  the six are documented too. The attribute macros are inlined into the facade (`undra::api` ...), so `undra-macros`
  is left out, as are `-bindgen`, `-cli`, `-ffi` and `-transport` (nothing an app core imports). rustdoc's `ayu` theme is
  the default (closest of its three to `#0a0a0a`); `rustdoc-header.inc` lays the site's palette (both themes), Geist, the
  icon and the sidebar logo over rustdoc's own CSS variables, and follows the site's theme choice (same origin, the
  `undra-theme` key) or `?theme=`. Layout is rustdoc's.
* **Swift, Kotlin, TypeScript** (`/reference/{swift,kotlin,typescript}.html`, committed, generated by
  `build-reference.mjs`): a one-sentence intro (what, the schema hash it was generated from, the playground), then one
  section per generated file in the order of the TypeScript barrel: Types, Errors, Objects, Stores, Ports, Queries, Wire
  ids (and, for TypeScript, the entry point). Each section: a line on what the file holds, the names it declares, and the
  declarations behind a "show" toggle (the `reveal-code` collapse the landing page uses, moved from `home.css` to
  `base.css` so both share it; byte-neutral for the landing page's CSS budget). The file name links to the full source on
  GitHub. The three pages carry about 30 KB of declarations each (the generated files are 360 KB, most of it bodies).
* **Ports** is a section with a sentence and no code: the playground declares no port of its own (the ten standard ones
  come with the runtime), so `Ports.swift`/`Ports.kt`/`ports.ts` hold nothing. See open item 1.
* The docs nav gets **one row** ("Rust API", in Reference; an `external` row of `docs.json`: a link, no pager, no search
  entry) and the docs landing one card; each of the three API overview pages gets one "Reference" line pointing at its
  per-platform page. The per-platform pages wear the docs sidebar without being in it (`also` in `docs.json`), and the
  header marks Docs as current for them (`sync-chrome`).

## The reader (`site/scripts/decls.mjs`)

Read `crates/undra-bindgen` first: it has no declarations-only view (only `--docs`, which toggles doc comments), and
adding a flag is a crate change, so it is an open item (2). The reader is a small structural parser for the one shape
bindgen emits: comments and string contents are masked (Swift `\(...)`, Kotlin/TS `${...}` interpolation included), then
statements are split at depth 0 by `{`, `;` or a newline that does not continue the line, each is classified per language
and printed from the source text (so every doc comment and every signature is verbatim). 10 tests
(`decls.test.mjs`, run in CI): one fixture per language, the masking, the fold, and an invariant check on the committed
playground bindings (no body text in the output, braces balance, every doc line is in the source).

Kept: everything an app can see, with its doc comment. Dropped: bodies, property initializers (`let`/`const val` and an
untyped property keep their value: ids, raw values), imports/`package`, private/internal/protected members, `override`
members (`apply`, `encode`, `decode`, `equals`: the plumbing; Swift's `undraEncode`/`undraDecode` are `public` and
stay), `init {}` blocks, constructor delegation, ordinary comments, the `async` keyword in TypeScript signatures (the
`Promise<T>` says it). A container whose members were all dropped prints `{ … }` (Kotlin's `companion object : UndraCodec<X>`).
A run of six or more consecutive lines that differ only by digits is folded to its ends with a count: the benchmark
store's 128 counters, in all three languages (`// … 126 more with the same shape …`).

Limits (also in the file's header): visibility is read from modifiers only; an initializer that is a block, Kotlin
accessors, Swift `where` on its own line and `#if`, TypeScript overloads and an object-literal return type are not
read; the fold is by the shape of consecutive lines. Package manifests (`Package.swift`, `build.gradle.kts`,
`package.json`, `tsconfig.json`) are generated too but are packaging, not API, so they have no section; a *source*
file with no section fails the build (so a new generated file kind shows up), and so do generated files that disagree
about the schema hash.

## CI and tooling

* `site.yml`: a step `bash site/scripts/build-rustdoc.sh` (`RUSTDOCFLAGS="-D warnings --default-theme=ayu --html-in-header ..."`,
  `cargo doc --no-deps --locked -p ...`; today it passes clean, so a pub item without docs, a broken intra-doc link or any
  rustdoc warning fails the site build, R4), `node --test site/scripts/decls.test.mjs`, then the existing "generated files
  are up to date" step, which now covers the three pages (`build-reference` is in `build-all`). `pull_request` paths gained
  `crates/**`, `Cargo.toml` and `Cargo.lock` (the doc comments are the Rust reference; `push` already had them).
* `stage.sh [dir]` copies `target/doc` to `reference/rust/` and writes a redirect `index.html` (a set of crates has no
  index); it refuses to empty `/`, `.`, the repo or `$HOME`. `build-rustdoc.sh` removes `target/doc` first, so a restored
  cache cannot leak other crates into the site. `build-local.sh` builds it too.
* `check-links.mjs`: rustdoc's own pages are not checked (their links are rustdoc's under `-D warnings`), links from the
  site into `reference/rust/` are skipped in the source tree and must resolve in the staged one.
* `build-search-index` and `build-llms` take the `also` pages: 25 search entries (a page entry and one per section for each page, the names under each heading),
  a "Reference" group in `llms.txt` with the Rust reference; `llms-full.txt` gets the intro, names and links (the collapsed
  code is left out of it as everywhere; the declarations themselves are one click away on the page). `sitemap.xml` has
  the three pages (a `dateModified` in each page's JSON-LD, hand-kept as for every page).

## Open items

1. The playground declares no custom port, so the Ports section has no generated example (the standard ports are in the
   runtimes and in the bindgen `ports` golden). Add a small port to `examples/playground/core` (with its contract rows)
   so the reference, the contract tests and R10 all show one. Crates/playground were out of scope here.
2. `undra bindgen --declarations` (a declarations-only emit per language from the schema, no parsing of text) would
   replace `decls.mjs` and be exact; it is a crate change (undra-bindgen, goldens, SPEC 10 note). The reader's tests
   would become its golden.
3. The rustdoc pages have no link back to the site (rustdoc has no slot for it short of `--html-before-content`, which
   would be chrome `sync-chrome` does not manage); the docs nav, the docs landing and the per-platform pages link in.
4. `undra-macros`' own docs (the six attribute macros) are reached through the facade's inlined `attr.*` pages only;
   if a macro grows long docs worth their own crate page, add `-p undra-macros` to `build-rustdoc.sh`.
