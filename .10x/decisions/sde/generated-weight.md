# `generated-weight`: generated code is an artifact; the schema is the API (ADR-062)

Worktree `wt/generated-weight`, from `main` `b909739`, 9 commits, merged with `main` at the end. Author: the implementer of the piece.
Reviews: none yet. One ADR: ADR-062 (Accepted, with an implementation note). Brief: user feedback U7/T5 ("two features already produced
about 1,400 lines of generated bindings; that's a lot of noise in reviews and in API versioning"), the design decided by the lead. No
wire, ABI, schema, schema-hash or generated-declaration change: no existing golden moved but by a header line.

## What landed

* **Provenance** (`crates/undra-bindgen/src/provenance.rs`): `sentence` / `line_comment` (the header every Swift, Kotlin and TypeScript
  file already had, now one function, text unchanged: a CLI test reads the hash out of `Ids.kt`'s line) and `GITATTRIBUTES`. `ts/package.json`
  gains a `"//"` member and `ts/tsconfig.json` a `//` line with the sentence (the only generated files that could carry one and did
  not). Goldens: 20 cases x 2 files, one line each (40 insertions, no deletion); `tests/provenance.rs` + `golden/provenance/{headers.txt,
  gitattributes.txt}`.
* **`.gitattributes`** (`crates/undra-cli/src/bindgen.rs`): `swift/`, `kotlin/` and `ts/` each get `* linguist-generated=true` (no `-diff`),
  files of the manifest, so `--check` fails when one is missing or edited. All six committed trees regenerated by `undra bindgen --docs`
  (`ios15-sample` without): 3 new files + 2 header lines each, 26 insertions and no deletion among tracked files.
* **`undra schema diff`** (`schema_diff.rs`, `commands/schema.rs`): two files, or `--against <ref> [FILE]` (the file as committed at the ref,
  `git show`, nothing built); every change a line `breaking` or `additive` by SPEC 2.6; fixed order; `--exit-code`.
* **`undra schema export`** (`schema_file.rs`): the core's schema as the file `diff` reads, every type and every small definition on one line:
  the playground's is 3,305 lines (pretty form: 8,799). Not in the brief; see Deviations.
* **Docs**: SPEC 2.6, 10, 13; ONBOARDING 5; `.github/pull_request_template.md` (the **Public API** line, on top of `pr-gate`'s template); the
  page `site/docs/reviewing-generated-code.html` (listed in `site/data/docs.json`, "Test, ship, operate"); `undra schema` in
  `site/docs/cli.html`; the site regenerated (`node site/scripts/build-all.mjs`: nav of every docs page, sitemap, search index, llms files,
  the errors page with the new C0009 message).
* **Measurement**: `scripts/generated-weight.mjs` (+ test).

**Reading it.** (1) Code is 77 to 85 percent of a tree: the volume is what R3 buys (a native observable class, a decoder per signal, a
documented wrapper per method), not boilerplate that a flag would drop; doc comments are 9 to 17 percent (R4). (2) `Stores` is 48, 47 and
43 percent of a tree, and **one fixture**, the `Bench` store (128 `UInt32` counters, a 10,000-row keyed list, three methods; there to measure
the boundary), is 1,698 of the Swift lines (22 percent of the tree), 1,325 of the Kotlin (18) and 1,082 of the TypeScript (14). The median of
the other fourteen stores is about 125 lines per platform (Swift 128, Kotlin 122, TypeScript 124; the largest, `Workshop`, 325 to 366), and
one real feature is 130 to 250 per platform: the feedback's "230 lines per feature per platform" is right, and two features on three
platforms are its 1,400. (3) What the schema says: 15 stores (164 signals), 30 records, 26 enums, 4 objects, 58 free functions, 18
constructors and 82 methods (158 callables), 4 queries and 4 mutations, 16 ports of 39 methods (`undra schema export`). The brief's "16 stores and
167 public functions" is 15 and 158 callables + 8 queries/mutations = 166 in this checkout.

**What a review sees.** On the CLI tests' to-do fixture (`tests/fixtures/schema-diff`, twelve API changes of every kind): the bindings
change by **506 lines** (Swift 160, Kotlin 170, TypeScript 176; `undra bindgen --schema` on both, `diff -r`, added + removed lines),
`schema.json` by **60**, and `undra schema diff` prints **12**.

**Avoidable padding** (counted in the playground; none implemented, each needs a helper in all three runtimes: SPEC 17, and room in a
TypeScript runtime that sits at 15,679 of 16,000 gzipped bytes, ADR-057; none changes a public shape, so none needs an ADR of its own for R11,
but each changes what generated code calls, so each is a piece):

| Candidate | Occurrences | Saving |
|---|---:|---|
| a fire-and-forget method's `try`/`catch`/`report` around one `callSync` (9 lines Swift, 10 Kotlin, 10 TypeScript) | 48 per platform | about 5 lines each: ~240 per platform |
| Swift `apply(signal:)`: two empty arms (`keyedPatch`, `lazyListInvalidated`) for a plain signal | 176 | 4 lines each: ~700 (9 percent of the Swift tree); a `default: break` would give up the compiler's check that a new `ChangeOp` case is handled, so not recommended |
| `Ids`: one constant per wire id | 283 to 290 lines | none: the ids are the content |

The `Bench` fixture is not padding in the generator; if the playground's own numbers should stop misleading, move it to a second core.

## Decisions and deviations (each with its reason)

1. **The header was already there** on every Swift, Kotlin and TypeScript source (the brief assumed it was not). The brief's "goldens
   regenerated for the header line only" holds: the diff is the two JSON files. Files that do not depend on the schema (C entry, module map,
   R8 rules, `Package.swift`, `build.gradle.kts`, `.gitignore`) keep a hash-less "Generated ... do not edit": a hash in the C header would
   move on every API change and say nothing about it.
2. **`.gitattributes` per tree, not at the output root**: a tree (the Swift package, the Gradle module, the npm package) is what an app includes
   or publishes on its own; `.undra-generated` stays uncollapsed (a few dozen lines that change when a file is added). A hand-written file kept
   in a tree is collapsed too (`*`); a nested `.gitattributes` with `-linguist-generated` restores it (said in the ADR and the page).
3. **`--against` reads a committed file; it does not build the core at the ref** (a worktree of the ref, a second `dlopen`: a full compile per run,
   toolchain-dependent, untestable without a build; ADR-062 "Alternatives"). So a project needs a committed `schema.json`, and:
4. **`undra schema export` is an addition to the brief.** Without it a project had no way to make the file `--against` reads (the dev runner's
   `--print-schema` is built under `target/undra/`). It is 25 lines over `schema_from_core`, plus the one-line-per-small-definition writer.
   If the lead prefers it as a `bindgen --schema-out`, the writer (`schema_file::render`) moves unchanged. No `export --check` yet:
   `undra schema export -o schema.json && git diff --exit-code schema.json` does it.
5. **Rules the brief left open** (SPEC 2.6): an **enum case added is breaking**; a port added is breaking unless it is a standard port; "optional
   field" is a field marked `#[undra(default)]`; behaviour a signature does not show (a query's stale time) is "additive", i.e. compatible; signals
   reordered is additive. Each is a line in `schema_diff.rs` and a test, and a one-line change if the lead disagrees.
6. **No new C code.** Errors use C0002 (not a schema), C0003 (no `git`), C0009 (the arguments do not make a comparison, a ref without the
   file, outside a repository) and C0010, in the R8 shape; one new golden (`C0009-schema-diff.txt`) for the errors page.
7. **The PR template**: `.github` had only workflows when this piece started; `pr-gate` added one at the same time (merged from `main`), so the
   merge keeps its four lines and adds this piece's **Public API** line.

## Not verified, and for the integrator

* GitHub's collapse of the trees (the attribute is documented behaviour; the draft PR shows it).
* The Swift and Kotlin typechecks were not re-run: only two TypeScript JSON files changed in the generators.
* `scripts/generated-weight.test.mjs` is not wired into CI (`ci.yml` is shared): add it beside `bench-device-report.test.mjs`. A CI step for
  the repository's own examples (a committed `schema.json` each, `schema export` + `git diff --exit-code`, `schema diff --against origin/main
  --exit-code`) is the dogfooding of R10 and was not added for the same reason.
* **Coordination with the `bazel` piece**: it writes the lint exclusions (ktlint, SwiftLint, ESLint fragments) next to the generated trees; none
  is written here. It owns `.gitattributes` text nowhere: this piece does (`undra_bindgen::provenance::GITATTRIBUTES`), and a Bazel rule that
  lists the outputs of `undra bindgen` should list `<tree>/.gitattributes` too.
