# ADR-055: The testing kit: `undra.recording`, `PreviewCore`, `RecordedCore` and port replay sit beside the runtimes and change nothing generated

Status: **Accepted** (2026-10-01, piece F1/F2 of the v1.x plan, `wt/testkit`). Touches: a new crate `undra-testkit`
(re-exported as `undra::testing`), a tap hook in `undra-transport`, `undra dev --record` and its generated runner
(`undra-cli`), one catch-all in `undra-runtime::testing`, three kits (`UndraTestKit`, `dev.undra:testkit`,
`@undra/testkit`) and a small seam in the Swift and Kotlin runtimes. It does **not** touch the envelope (3.2), any
payload, the C ABI, the wasm ABI, the schema or a generated shape: no schema hash moves, no golden file changes.
Constitution R11 (decided before the code); the design note is `.10x/decisions/architect/testkit.md`.

## Context

An app on Undra is previewed and tested today with the real core only (slow to reach states, real ports) or with
Rust fakes (core tests, nothing in a SwiftUI preview, a Compose test or a story). Two things are missing: the real
core running in the process with deterministic ports and a clock the test owns, and a way to capture a session once
and play it back (as a screen state, or as the script for the ports of a test).

The constraints that shaped it: the C ABI and the wasm ABI have no entry to install a Rust fake into a core, and
adding one is a boundary change (R11) for a testing convenience; every port of a native or wasm core is implemented
by the host anyway; and the dev server already sees every envelope of every platform.

## Decision

1. **One recording format, `undra.recording` version 1.** JSON: `{format, version, schema_hash, source, platform?,
   events}`; an event is `{t, kind, ...}` with `t` whole milliseconds since the session start; payloads are lower-case
   hex of the bytes SPEC 3 defines; handles are `"0x%016x"` strings (a u64 does not fit a JavaScript number); ids are
   numbers. Kinds: `call`, `reply`, `change_set`, `stream_item`, `port_call`, `port_reply`, `event`, `timer_fired`,
   `observe`, `release`, `cancel`. Port and method ids are authoritative; `name` (`"Http.request"`) is informational.
   The writer is canonical (fixed key order, one event per line, no wall-clock, no host paths), so equal sessions are
   equal bytes; every kit's writer is golden-tested byte for byte against `testkit/fixtures/*.json`. A reader refuses
   another `format` or `version` with a typed error naming the field and the event. The seed document (`version: 1`)
   is a second, smaller format for the fakes.
2. **Capture in two places, one format.** `undra dev --record FILE` taps the dev server (`undra_transport::FrameTap`,
   in `ServerConfig`): every frame in both directions, for iOS, Android and web alike; the runner also wraps its
   Rust-bound `Clock` and `Rng`. A reload starts a new core and so a new file (`NAME-2.EXT`). `PortRecorder` (each
   kit) and `Recorder` (Rust) record port traffic where there is no dev server.
3. **`PreviewCore`: the real core, platform-native fakes.** Each kit carries the fakes of `undra::ports::fakes`
   natively (FakeClock+Timer, SeededRng `xorshift64*`, FakeHttp, MemKv/MemSecureStore, MemFs, CaptureLog, scripted
   Connectivity and Lifecycle) and registers them as the adapters of the app's own core. `testkit/conformance/fakes.json`
   is generated by the Rust fakes (a Rust test fails when it is stale) and replayed against all three kits, so they
   cannot drift. `PreviewCore.load(seed)` takes the seed document or native builders. `advance(ms)` moves the manual
   clock one deadline at a time, firing due timers, and waits for the core to be idle.
4. **`RecordedCore`: a replay transport under the unchanged runtime.** The generated stores, the mirror and
   `UndraCore` are the real ones. A manual playhead releases the recorded change-sets; an observe delivers everything
   recorded up to the playhead; a constructor, method, function or page call is answered by the next recorded reply for
   the same target (call ids rewritten); a call with no recorded reply is a typed refusal naming it. For states that
   are costly to reach, not a simulator of the core.
5. **`Replayer`: a recording as the script of the ports.** Per-port queues in recorded order; a call that matches the
   next recorded one (method and, by default, exact arguments) gets the recorded reply; anything else is `Unavailable`
   and a typed `ReplayError` (`mismatch`, `exhausted`, and `unconsumed` at `finish`). A deviation consumes nothing.
   Time is metadata: replay is instant and deterministic.
6. **Seams in the runtimes, additive.** Swift: `UndraTransport`, `UndraInbound` and `UndraCore.attach(transport:)`
   become `package` (same SwiftPM package; still hidden from apps). Kotlin: `Transport`, `TransportEvents`,
   `PortOutcome` and `UndraCore.attachTransport` are public behind `@UndraEmbeddingApi` (an opt-in at error level).
   TypeScript already exported `Transport` and `UndraCore.attach`. SPEC 17.5 describes them.
7. **Rust.** `undra-testkit` holds the format, `Seed`, `Recorder`, `Replayer`, `Harness` and the conformance
   generator, and builds for wasm32 (the CI loop covers it). `undra-runtime::testing` gains `script_port_default` and
   `TestRuntime::with_host`; `undra-transport` gains only the tap.
8. **Storybook is not a dependency.** The playground's web stories are Component Story Format modules rendered by a
   plain page with Vite; Storybook loads them unchanged.

## Consequences

* Generated code, the wire, the ABI and the schema are as before. A project that does not use the kit loads none of it
  (the kits are separate products; `undra::testing` is stripped from a core that does not reference it).
* The kit depends on public behavior (the runtimes' seams) that is now part of what a runtime change must keep working;
  the contract runners (`contract-tests/*`) exercise PreviewCore and RecordedCore against the real core on all three.
* **Known limits, stated in `docs/TESTING.md`:** a native core's `ctx.sleep` runs on the runtime's own timer thread in
  real time (the C ABI never hands sleeps to the host), so the manual clock moves what the core reads and timers armed
  through the `Timer` port, not a native sleep (on the web it moves sleeps too); in Swift, start-up work of the core
  runs concurrently with the host registering ports (SPEC 6), so a preview must not rely on a persisted cache being
  hydrated; `RecordedCore` does not replay port traffic, rewind or simulate; the Android preview pane runs on a
  desktop JVM and uses `RecordedCore`.
* A change to the recording format is a new `version`, with the old one still read for as long as a checked-in
  fixture has it; a new event kind is a minor, additive change that older readers refuse by name.

## Alternatives considered

* **An ABI entry to install Rust fakes into the core.** Rejected: a boundary change for a convenience, and the ports
  are implemented by the host on native and wasm anyway.
* **Recording only in the runtimes.** Rejected as the only path: the dev server sees all three platforms with one
  tap. Kept for non-dev sessions as `PortRecorder`.
* **A binary recording.** Rejected: a recording is a fixture, so it is reviewed, diffed and hand-edited. Hex doubles
  the size and nobody notices.
* **Storybook as a dependency.** Rejected: a large toolchain for a rendering host; CSF is the portable part.
