# ADR-062: Generated code is an artifact; the schema is the API

Status: **Accepted** (2026-10-02). Decided by the lead after user feedback U7/T5; implemented by `wt/generated-weight` (record:
`.10x/decisions/sde/generated-weight.md`). It adds a file to each generated tree, a header line to two generated files, and a
command (`undra schema`); it does **not** touch the wire, the C or wasm ABI, the schema, the schema hash, the runtimes, or the
shape of any generated declaration an app can see (R11: nothing here needed a boundary ADR; this one records a tooling and review
decision). SPEC 2.6 (new), 10 and 13 are amended in the same commits. Constitution R1 (the schema is the only truth), R3 (generated
code passes native review), R4 (every feature lands whole), R7 (compatibility is checked at load and at build).

## Context

The feedback: "Two features already produced about 1,400 lines of generated bindings. That's a lot of noise in reviews and in API
versioning." It is accurate. The playground (`examples/playground`, constitution R10) generates, per platform:

| | Swift | Kotlin | TypeScript |
|---|---:|---:|---:|
| Lines | 7,787 | 7,365 | 7,692 |
| Code | 6,626 (85%) | 5,698 (77%) | 6,121 (80%) |
| Doc comments | 699 (9%) | 1,263 (17%) | 1,170 (15%) |
| Other comments, blank | 462 (6%) | 404 (5%) | 401 (5%) |
| `Stores` file alone | 3,737 | 3,430 | 3,268 |
| of which the `Bench` store | 1,698 | 1,325 | 1,082 |

(`node scripts/generated-weight.mjs`, new with this ADR; the per-kind tables are in the record and the docs page "Reviewing
generated code and versioning the API".) Three things follow from the shape, and they set the decision:

1. **The volume is mostly code, and the code is what R3 buys.** A store is a native observable class with typed members, a decoder
   per signal and a documented wrapper per method; there are no two ways to write it that a Swift, Kotlin or TypeScript engineer
   would both call native and that are much shorter. The doc comments (9 to 17%) are R4. Generating less is not the fix.
2. **The playground's own figure is inflated by one fixture.** `Bench` is the benchmark store: 128 `UInt32` counters, a keyed
   10,000-row list and three methods. It is 22% of the Swift tree, 18% of Kotlin and 14% of TypeScript. One real feature of the
   playground, `Counter`, `Notes` or `Todos`, is 130 to 250 lines per platform: the feedback's "230 lines per feature per
   platform" is right, and two features on three platforms are the 1,400 lines it counts.
3. **The cost is paid in two places that are not the generated text.** A reviewer who reads generated files is wasting the review
   (the files are proven by `undra bindgen --check`, which regenerates them from the schema and compares byte for byte), and an
   API that is versioned by the diff of its generated files has no version: the change that matters (a function lost a parameter)
   is one line in a schema and thirty in each of three languages.

Already true today and not changed: every Swift, Kotlin and TypeScript source file starts with `Generated by undra-bindgen from
the Undra schema of `<crate>` (schema hash 0x<hash>). Do not edit.`, the files that do not depend on the schema (`Package.swift`,
`build.gradle.kts`, the C header and module map, the R8 rules, `.gitignore`) say `Generated ... Do not edit` without a hash, and
`undra bindgen` writes `.undra-generated`, the list of what it wrote, so a file that is no longer generated is removed and a file
beside them is never touched.

## Decision

### 1. Generated code is an artifact: it says so, and the host collapses it

**1.1 The header.** Every generated file that can hold a comment starts with one line that names the generator, the core, the
schema hash and "Do not edit". Two files did not have one because their format has no comments: `ts/package.json` gets a
`"//": "Generated by undra-bindgen from the Undra schema of `playground-core` (schema hash 0x...). Do not edit."` member (npm
ignores unknown members; `//` is the convention for a comment in a package manifest) and `ts/tsconfig.json` starts with the same
sentence as a `//` comment (TypeScript reads `tsconfig.json` as JSONC). The sentence is one function in `undra-bindgen`
(`provenance::sentence`) used by all four writers, so the text and the hash are spelled once. The files that do not depend on the
schema keep a header without a hash on purpose: a hash in the C header would move on every API change and say nothing about it.
The text of the existing headers does not change (a test reads the hash from `Ids.kt`'s line).

**1.2 `.gitattributes`.** `undra bindgen` writes `<out>/swift/.gitattributes`, `<out>/kotlin/.gitattributes` and
`<out>/ts/.gitattributes`, each with the same text:

```gitattributes
# Generated by `undra bindgen`: do not edit, it is rewritten with the bindings.
# GitHub collapses these files in a pull request and leaves them out of the language statistics.
# Review the schema (`undra schema diff`), not the bindings: `undra bindgen --check` proves they
# match it. A collapsed file opens to its full diff when you click it.
* linguist-generated=true
```

`linguist-generated=true` is the attribute GitHub's diff view reads to collapse a file ("Generated files are not rendered by
default") and to leave it out of the repository's language bar. **`-diff` is not set**: it would make `git diff`, `git log -p`
and every other tool print "Binary files differ", and the point is that the diff stays one click or one flag away. The file is one
of the tree's files in the manifest, so `--check` fails when it is missing or edited and a later run removes it with the rest. It
is per tree (a tree is what an app includes: the Swift package, the Gradle module, the npm package, each can be copied or
published on its own and then still carries its attribute); `.undra-generated` itself, a few dozen lines that change only when a
file is added or removed, is not covered. `*` also matches a hand-written file somebody keeps inside a tree (the manifest
protects it from deletion, not from collapsing): a nested `.gitattributes` with `-linguist-generated` next to it restores it, and
the docs page says so.

**1.3 Not done here.** Lint exclusions (ktlint, SwiftLint, ESLint fragments next to the trees) belong to the Bazel piece; the files
this ADR adds are exactly the ones such a fragment would want to ignore, and nothing here conflicts with it.

### 2. The schema is the API: `undra schema diff`, and the file it reads

**2.1 The command.**

```text
undra schema diff <OLD> <NEW> [--exit-code]                 two schema JSON files
undra schema diff --against <REF> [FILE] [--exit-code]      FILE as committed at the git ref, against FILE in the working tree
undra schema export [-o FILE] [--docs] [--release] [--check]   the core's schema as the file the two above read
```

`OLD`, `NEW` and `FILE` are schema JSON in any form `undra bindgen --schema` reads (the whole schema, the canonical form). `FILE`
defaults to `schema.json` in the project's directory (the current directory outside a project). `--exit-code` makes the command
exit with status 1 when the diff has a **breaking** line, as `git diff --exit-code` does for any difference; without it the
command prints and exits 0, so a reviewer can run it freely. Errors use the codes the CLI has (a file that is not a schema is
`C0002`, a ref or a repository the command cannot use is `C0009`, a missing `git` is `C0003`, an unreadable file `C0010`), each in
the four-part shape of R8.

`--against` reads the file at the ref with `git show <REF>:<path>`: **it does not build the core at the ref**. The alternative
(a temporary worktree of the ref and a second `dlopen` of a second build, as `cargo semver-checks` does with rustdoc) costs a full
compile of the core and every dependency per run, depends on the toolchain of the ref, and cannot be tested without building; a
committed snapshot is hermetic, fast and itself reviewable (it is the API as text). The cost is that a project keeps a
`schema.json`: `undra schema export -o schema.json` writes it from the built core (without doc comments unless `--docs`, so a doc
fix is not an API change), and a CI step `undra schema export --check` keeps it as honest as `undra bindgen --check` keeps the
bindings (amended in review: see the end; the first text had `export -o schema.json && git diff --exit-code schema.json`).

`schema export` writes the exchange form of SPEC 2.3 with every type on one line (the compact form SPEC 2.1 gives) and every small
definition that holds nothing nested (a field, a parameter, a signal, a case without a payload) on one line of at most 140 columns,
in declaration order: the playground's file is 3,305 lines where the pretty-printed form is 8,799 and the Swift tree alone is 7,787,
and a field that became optional is one changed line, not six. It is the same JSON; every reader reads both.

**2.2 Output.** One line per change, grouped by item, in a fixed order (types, objects and stores, functions, ports, callbacks,
queries; by name within a group; members in the order their definition lists them), each line `breaking` or `additive`:

```text
Public API: old.json (schema 0x3c17cd5f59bb6f68) -> new.json (schema 0x91d2b6e0aa51f3c4)

breaking  field Todo.title: type changed from String to Option<String>
breaking  field Todo.due: added (Option<Timestamp>, with a default): Swift and Kotlin initializers default it, but a TypeScript object literal that builds a `Todo` must name it
breaking  method Todos.add: parameter `tags: Vec<String>` added
additive  function archive: added (fn archive(id: TodoId) -> Result<(), TodoError>)
breaking  case Status.Archived: added (an exhaustive switch or when stops compiling)

4 breaking, 1 additive.
```

The text is for people and is not a stable format; the order is (tests pin it). It is on stdout; progress and warnings stay on stderr.

**2.3 The compatibility rules (SPEC 2.6).** The question a line answers is: *does code an app wrote against the old schema's
bindings still compile and mean the same against the new ones?*, in each of Swift, Kotlin and TypeScript. A **removed or changed
signature is breaking; an added function, method, store, object or record is additive; an added record field is breaking even with
a default**, because a TypeScript record is an interface whose object literals name every member (amended in review). In full:

| Item | Additive | Breaking |
|---|---|---|
| record, enum, error, object, store, function, query, mutation, callback | added | removed |
| record | | becomes or stops being a newtype |
| record field | `default` gained; `default` lost on a field of a record or enum type (no initializer spelled it) | added, with or without `#[undra(default)]` (a TypeScript object literal names every field; Swift and Kotlin default only an appended field of a primitive, string, time, optional or collection type); removed; type changed; fields reordered; `default` lost on any other field |
| enum case | message of an error case changed | added (an exhaustive `switch` / `when` stops compiling); removed; payload changed; index changed (the wire value moved) |
| enum | | error flag changed |
| object, store | | store added to or removed from an object |
| constructor, method (an object's or a port's or a callback's) | added to an **object** or an **event port** (the app calls it); `ctx` taken or not (no generated signature shows it) | removed; added to a sync or async **port** or a **callback** (the app implements it); parameter added, removed, renamed, retyped or reordered; return type, `async`, generic label changed |
| store signal | added; `no_coalesce`, `default`, `computed`, `key` changed (no generated declaration shows them); signals reordered | removed; type changed |
| function | added | removed; any of the method changes above |
| query, mutation | added; `key`, `stale`, `persist`, `idempotent`, `interval`, `poll_in_background` changed; a paged query's cursor type, or an item key other than `id` | removed; kind, parameters or return changed; `infinite` added or removed; the item key changed to or from `id` |
| port | a standard port of SPEC 8 added (the runtimes ship and register it); an **event** port added (the app sends, implements nothing) | an opt-in standard port of SPEC 8.1 added (a web app registers its adapter); any other port added (the app must supply an adapter); removed; kind changed |
| callback | a method's `coalesce` changed | `background` changed (the calls move on or off the main thread; Swift's protocol gains or loses `@MainActor`) |

"Additive" means *compatible*: it includes a behavioural change that no signature shows (a query's stale time). Ids are not
compared (every id but a signal's position derives from a name, SPEC 1.1). Documentation is not compared. When two schemas have
different hashes and the rules find nothing, the command says so rather than "unchanged". A rule can be wrong for an app that
uses only part of the API; the labels are conservative (what breaks in any one of the three languages is breaking), and
`--exit-code` is a gate a team chooses to run, not a proof.

### 3. The review rule

**Review the schema diff, not the bindings; the bindings are proven by `--check`.** A pull request that changes a core's public
surface changes `schema.json` (a few lines) and the bindings (collapsed by GitHub, proven by CI). The reviewer reads
`undra schema diff --against <base>`; the author writes the same output into the description when a line is breaking. This is in
`docs/ONBOARDING.md`'s contributing notes, in the new docs page, and as a line in `.github/pull_request_template.md`
("Public API change? `undra schema diff --against <base>` pasted, breaking lines justified").

### 4. The measurement, and the padding it found

`scripts/generated-weight.mjs [tree] [--json]` prints, per platform and per kind of generated file (types, errors, objects,
stores, ports, queries, callbacks, ids, core, index, package files), the lines that are code, doc comments, other comments and
blank (`node --test scripts/generated-weight.test.mjs`). The tables are in the record and the docs page; this ADR keeps the
conclusions. **Avoidable padding, listed with its saving, none implemented here:**

| Candidate | Where | Occurrences in the playground | Saving if held by a runtime helper |
|---|---|---:|---|
| a fire-and-forget method wraps `try`/`catch`/`report` around one `callSync` (9 lines in Swift, 10 in Kotlin, 10 in TypeScript) | `Stores`, `Objects` | 48 per platform | about 5 lines each: 240 per platform |
| Swift's `apply(signal:)` spells two empty arms (`keyedPatch`, `lazyListInvalidated`) for a plain signal | `Stores` | 176 | 4 lines each: 700 in Swift (9%); a `default: break` would drop the compiler's check that a new `ChangeOp` case is handled |
| `Ids`: one constant per wire id | `Ids` | 286 / 290 / 283 lines | none: the ids are the content |

Every one needs a runtime change on three platforms (a helper the generated code calls, SPEC 17, and for TypeScript room in a
runtime that sits at 15,679 of its 16,000 byte budget, ADR-057), so each is its own piece with its own ADR if the generated shape
moves; none changes a public shape, and none was needed to meet the goal of this ADR. They save at most 10% of a tree; the review
cost is addressed by 1 to 3, which take 100% of the generated text out of review. The effect on a review, measured on the fixture of the
CLI tests (a to-do core and a change with twelve API changes of every kind): the bindings change by **506 lines** (160 Swift, 170
Kotlin, 176 TypeScript), `schema.json` by **60**, and `undra schema diff` prints **12**.

## Alternatives considered

* **Generate at build time and do not commit.** The strongest answer to "noise in reviews": no generated text in the repository at
  all. Rejected for now: the committed bindings are what a native reviewer's IDE indexes, what a Swift package or a Gradle module
  consumes without running `undra`, and what `undra bindgen --check` keeps honest; a clone that builds needs the Rust toolchain
  before its Swift opens. The Bazel piece (generated trees as build outputs, hermetic) makes this an option for teams that want it,
  and nothing here prevents it: a `.gitignore` on the tree is the whole change.
* **A terser doc mode, or fewer comments by default.** Rejected: R3 and R4. Docs are 9 to 17% of a tree and the reason a native
  engineer can use the bindings without the Rust source open; `--docs` already makes them optional where the app wants none.
* **`-diff` on the trees.** Rejected: it hides the content from `git diff`, `git log -p`, blame views and every non-GitHub review
  tool, and a reviewer who suspects the generator needs the diff most.
* **`--against` builds the core at the ref.** Rejected, above: minutes per run, toolchain-dependent, untestable without a build.
* **Hash the schema and compare hashes.** The hash says *that* the API moved (every file already carries it); the point is to say
  *what* moved. Kept as the footer of the diff.
* **Parse the diff out of the committed bindings.** The bindings are generated from the schema; the inverse is not defined, and it
  would make the generated code, not the schema, the thing a tool reads (against R1).

## Consequences

* A pull request's generated files are collapsed on GitHub; their diff is one click away. `schema.json`, where a project commits one, is
  the reviewable API; `undra schema diff --against origin/main --exit-code` is a CI gate.
* `undra bindgen` writes three more files per project (`.gitattributes` in each tree) and two JSON files gain a header: every
  committed tree (`examples/*/generated`, the goldens of `undra-bindgen` and `undra-cli`) changes by exactly those lines. No
  generated declaration changes, so nothing an app imports moves and no schema hash moves.
* `undra-cli` gains the `schema` command (`diff`, `export`), `undra-bindgen` the `provenance` module; no new dependency, no unsafe.
* A project that has no committed schema file gets nothing from `--against` until it runs `undra schema export -o schema.json` once;
  the error says so.
* Follow-ups, none blocking: the runtime helpers of section 4 (one piece, three runtimes); a GitHub Action that posts the diff as a
  comment; lint exclusions (the Bazel piece); a committed `schema.json` for the repository's own examples with the CI steps of the
  docs page (R10).

## Implementation note (2026-10-02, `wt/generated-weight`)

What differs from the text above, and what was measured while building it:

* **The header already existed** on every Swift, Kotlin and TypeScript source file (with the schema hash, in the same words); what
  was new is that the sentence is one function (`provenance::sentence`, used by the three generators and the two JSON files) and that
  `package.json` and `tsconfig.json` carry it. The goldens changed by those two lines per case (40 files, 40 insertions, no deletion);
  `tsc` accepts the JSONC `tsconfig.json` in all 23 typecheck cases.
* **`.gitattributes`** is per tree as decided; its text is `undra_bindgen::provenance::GITATTRIBUTES` (golden:
  `crates/undra-bindgen/tests/golden/provenance/gitattributes.txt`) and the CLI writes it (`undra_cli::bindgen::ATTRIBUTES_FILE`; the
  CLI's golden holds the three placed copies), the way it writes `kotlin/.gitignore`. Every committed tree was regenerated: five files
  per example (three new, two with a header line), 26 insertions and no deletion among the tracked files. GitHub's rendering of the
  collapse is documented behaviour of the attribute and was not observable from here.
* **`undra schema diff`** is `crates/undra-cli/src/schema_diff.rs` (pure: two `Schema`s in, a list of changes out; 35 unit tests, one
  per rule and both directions, and the order pinned) and `commands/schema.rs` (the arguments and the git side, scripted in nine unit
  tests; the CLI tests run it against two fixture schemas with a golden report, against `HEAD` and `HEAD~1` in a scratch repository,
  below the repository root, and on every error path). Choices the rules left open: **an enum case added is breaking** (an exhaustive
  `switch` or `when` stops compiling, as in Rust's own semver rules); a port is breaking to add unless it is standard; an `Option` field
  is not "optional" unless the author marked it `#[undra(default)]`, since that is what gives Swift and Kotlin initializers a default;
  signals reordered is additive.
* **`undra schema export`** is not in the brief and is what makes `--against` usable: a project had no way to produce a schema file
  without running the dev runner by hand. It reuses `undra bindgen`'s extraction (`schema_from_core`).
* **The measurement**, `scripts/generated-weight.mjs` and its test, is not yet run by CI (`ci.yml` is not touched from a worktree): add
  `node --test scripts/generated-weight.test.mjs` to the job that runs `bench-device-report.test.mjs`.
* **Not done**: committing a `schema.json` for the repository's own examples (R10 would say we should; it needs a CI step that keeps it
  current, which is `ci.yml`'s); the `bazel` piece's lint exclusions; any of the padding candidates of section 4.

## Amendment (2026-10-02, adversarial review)

The review (`.10x/reviews/2026-10-02-generated-weight-review.md`) checked each rule of 2.3 against what the three generators emit
and changed the ones that were wrong; SPEC 2.6 and `schema_diff.rs` changed with them, each with a test.

* **A field added is breaking even with `#[undra(default)]`.** The TypeScript generator writes a record as an interface whose every
  member is required, so an object literal typed as the record stops compiling; the first text called the line additive and the
  labels "conservative" while saying so. Swift and Kotlin default only a defaulted field of a primitive, string, time, UUID, decimal,
  optional or collection type (never a record or an enum: `default_value` in both generators), and a defaulted field inserted before
  an existing one shifts Kotlin's positional arguments and `componentN`. The line says which applies; a CLI test generates all three
  languages and checks the rule against them. Losing a default no initializer spelled is additive.
* **A callback's `background` changed is breaking**: Swift spells it as the protocol's isolation (`@MainActor` or not), and a call
  that arrives on another thread changes what an implementation that touches the UI may do, in every language.
* **False breaks removed**: an event port, and a method added to one, is additive (the app calls `<Port>Events`, implements nothing);
  `ctx` and a signal's `computed` and `key` are additive (no generator reads `takes_ctx`; every signal is a read-only property); so
  are a paged query's cursor type (`fetchNextPage()` takes none) and an item key that is not `id` before or after (only `id` makes
  Swift's row type `Identifiable`).
* **Standard means `stdlib::covered`** (name, id and shape, SPEC 10.5), not the name alone; an **opt-in** standard port (SPEC 8.1)
  added is breaking, since a web app must pass its adapter in `LoadOptions.ports`.
* **A stale schema file is caught.** `--against` builds nothing, so a `schema.json` nobody exported after an API change made the
  report say "No changes". It now reads the schema hash the project's bindings carry (`provenance::schema_hash_in`, the inverse of
  the header sentence) in the working tree and at the ref, and warns at either end where the file disagrees; a stale working-tree
  file fails `--exit-code`. `undra schema export --check` (a follow-up in the first text) is the CI gate of the file, failing with `C0007`.
* The CLI fixture gains an event port: thirteen changes, 7 breaking and 6 additive; the bindings change by 581 lines (183 Swift, 193
  Kotlin, 205 TypeScript), `schema.json` by 77, and the diff prints 13.
