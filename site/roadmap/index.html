Roadmap

What is shipped, in flight and next.

Undra v1.0 shipped on 30 September 2026. This page follows the project's working record, .10x/handoff.md, and changes with it. Last updated 30 Sep 2026.

Shipped

v1.0

30 Sep 2026

The framework you can build on today.

  • Records, enums, typed errors, objects

    Every public type comes from the schema and arrives in each language as that language would write it.

  • Stores, signals, computeds, keyed lists

    Reactive state in the core; list changes cross as O(change) patches.

  • Ten ports with adapters and fakes

    Http, Kv, SecureStore, Fs, Clock, Rng, Log, Timer, Connectivity and Lifecycle, with platform adapters and deterministic Rust fakes.

  • Queries and mutations

    Staleness, dedup, retry, optimistic rollback, an offline queue and persistence.

  • Streams and cancellation

    Streams with backpressure; cancelling a call drops its future.

  • Snapshot and restore

    Stores snapshot for crash recovery.

  • Schema-hash gate

    Checked at load and at build; a mismatched UI and core refuse to talk.

  • undra dev

    A live core over a WebSocket, rebuilt on save.

  • Teaching diagnostics

    Every macro error says what, why and how to fix it.

  • 18 contract scenarios on 3 platforms

    The same wire-level scenarios run against the real core on Swift, Kotlin and TypeScript: 54 of 54 pass.

  • Adversarial reviews of every core crate

    Signals, runtime, macros and ffi were each reviewed by someone who did not write them.

Now

v1.x

in flight

In flight for the v1.x releases.

  • Distribution

    brew, npm, a curl installer and cargo-from-git, each proved by a release dry run.

  • Harsh-conditions benchmark suite

    Very high-frequency data: firehose transactions, keyed-list churn, stream backpressure and a soak run, with CI budgets.

  • Device-measured benchmark rows

    The same benchmarks on an iPhone, an Android phone and Chromium, replacing host proxies.

  • A schema loader that survives dead-stripping

    So the tooling sees the schema in debug and release builds without linker flags.

  • Android undra dev remote mode

    The Kotlin runtime gains the WebSocket transport the web and iOS already have.

  • Dev-client auto-reconnect

    After a rebuild, a running app reconnects to undra dev on its own instead of needing a reload.

  • WeakCtx

    Long-lived tasks stop pinning a runtime that was dropped.

  • Macro diagnostic polish

    Better wording for the query-in-impl and split-impl cases.

  • Swift Port types public

    Custom ports in Swift without the bindgen fallback.

  • Full-JSON undra_schema_json

    So the dlopen-based bindgen keeps doc comments.

Next

v1.1 and v1.2

planned

Planned for the releases after v1.0. The order may change with what the benchmarks show.

  • crates.io publishing

    Publish the crates under a registry-safe prefix; needs its own ADR for the renames.

  • Frame-coalesced delivery

    Not shipped, and a runtime-model change that needs an ADR first. Today every change-set is applied on its own, in one main-thread hop per transaction; the stress suite decides whether coalescing per frame is needed.

  • Maven Central for the Kotlin runtime

    Depend on it from Gradle without a local build.

  • Windows CLI

    Release binaries and docs for the undra command on Windows.

  • undra upgrade

    Move a project to a newer Undra version.

  • Migration guides

    From Kotlin Multiplatform and from UniFFI.

  • A custom domain

    A home for the site and docs that is ours.

Later

Horizon

exploring

Directions under consideration, not scheduled.

  • Desktop targets

    macOS, Windows and Linux over the same C ABI.

  • A first-party inspector

    Time-travel over change-sets; the wire makes it natural.

  • A sync engine

    A separate package, not part of the core.

  • Compose Multiplatform interop

    Use an Undra core under a Compose Multiplatform UI.

Not planned

Not planned

Shared UI of any kind, and hosted services. Undra owns everything under the pixels and leaves the screens to SwiftUI, Compose and React.

How to influence the roadmap

Open an issue on GitHub and describe the problem you have rather than the feature you want; real projects and real numbers move items up. Anything that touches the wire, the runtime model, the threading model or a generated public shape needs a decision record first, and those live in .10x/adrs.
