Roadmap

What is shipped, in flight and next.

Undra v1 was finished on 30 September 2026, and the v1.x work since is merged on main; the first tag, v1.0.0, is still to cut. This page follows the project's working record, .10x/handoff.md, and changes with it. Last updated 2 Oct 2026.

Shipped

v1.0

30 Sep 2026

The framework you can build on today.

  • Records, enums, typed errors, objects

    Every public type comes from the schema and arrives in each language as that language would write it.

  • Stores, signals, computeds, keyed lists

    Reactive state in the core; list changes cross as O(change) patches.

  • Ten ports with adapters and fakes

    Http, Kv, SecureStore, Fs, Clock, Rng, Log, Timer, Connectivity and Lifecycle, with platform adapters and deterministic Rust fakes.

  • Queries and mutations

    Staleness, dedup, retry, optimistic rollback, an offline queue and persistence.

  • Streams and cancellation

    Streams with backpressure; cancelling a call drops its future.

  • Snapshot and restore

    Stores snapshot for crash recovery.

  • Schema-hash gate

    Checked at load and at build; a mismatched UI and core refuse to talk.

  • undra dev

    A live core over a WebSocket, rebuilt on save.

  • Teaching diagnostics

    Every macro error says what, why and how to fix it.

  • 17 contract scenarios on 3 platforms

    The same wire-level scenarios run against the real core on Swift, Kotlin and TypeScript: 51 of 51 pass.

  • Adversarial reviews of every core crate

    Signals, runtime, macros and ffi were each reviewed by someone who did not write them.

Since v1.0

30 Sep – 2 Oct 2026

Landed in the two days after v1.0; the record of each piece is in the repository.

  • The contract grid, grown to every feature

    Thirty-three scenarios run against the real core, 95 of 95 cells passing at the last merge (the web-only two on TypeScript alone).

  • Frame-coalesced delivery (ADR-031)

    The platform mirrors merge queued change-set entries once per frame, bound their backlog and re-observe on overflow; keyed-list firehoses cost ~10x less per frame on the web. Contract scenario S18 proves a 1,000-transaction burst applies in one drain on all three platforms.

  • Harsh-conditions benchmark suite and the live stress screen

    Firehose, event firehose, keyed churn, fan-out, stream backpressure, concurrent completions and a soak, with CI budgets that pass on the GitHub runner; the playground's stress screen shows the same numbers live in your browser.

  • Swift error channel (ADR-032)

    Generated Swift never traps: calls throw the method's own error, CancellationError or UndraCallError; commands report through onError.

  • A schema loader that survives dead-stripping (ADR-029)

    The loaded host core keeps its schema and JNI exports whatever else touched the target directory.

  • The name (ADR-030) and the wire magic (ADR-033)

    Keel became Undra before anything was published; the envelope's magic bytes read UNDR.

  • Measured on devices

    The benchmark rows come from the playground's bench hooks on the iPhone simulator, the Android emulator and Chromium, labelled as such; real-device rows the moment hardware is attached.

  • Android remote mode and auto-reconnect (ADR-051)

    The Kotlin runtime has the WebSocket transport; all three runtimes reconnect with backoff and resume a session after a rebuild, with the status visible in the app.

  • Every macro error teaches

    44 codes, each with what, why, fix and a link, each with a compile-fail test; the error-codes page regenerates from the catalogue.

  • The whole schema in undra_schema_json (ADR-050)

    The dlopen route keeps doc comments, and the Swift Port types are public, so custom ports need no fallback.

  • One error channel on every platform (ADR-032)

    Kotlin and TypeScript calls fail with the same closed UndraCallError set as Swift; commands report instead of throwing; a lost connection is state, not an error event.

  • No manual build step

    A Gradle task, an Xcode build phase and a Vite plugin run undra build; undra init emits CI; undra upgrade moves a project in lockstep; undra doctor names every fix.

  • The web bundle under its budget (ADR-052)

    The hello-world core ships under its 120 KB gzipped budget, measured and gated in CI, and the JavaScript a page loads up front has a gate of its own; the numbers on this site come from the record.

  • State-preserving reload (ADR-053)

    undra dev snapshots the old core and restores into the rebuilt one; the dev bar says whether the state was kept, and why not when it was not.

  • Derived keyed lists (ADR-039)

    A filtered, sorted view over a 10,000-row list costs what changed: one row edit is 158 bytes on the wire where it was 353 KB.

  • Devtools (ADR-054)

    A page served by undra dev: live stores, a change-set timeline with time travel, port and query logs, counters; behind a per-run token.

  • Persisted-state migrations and typed storage (ADR-037, ADR-049)

    A changed schema still restores what the last version stored; storage ports fail with typed errors on every platform; a crashed web core restarts from its last snapshot.

  • A testing kit for apps (ADR-055)

    Previews run the real core in process with scripted ports and a manual clock; a session recorded once with undra dev --record replays deterministically in tests on every platform.

  • WebSocket, SSE and Db ports (ADR-047, ADR-048)

    Real-time streams with the core's credit as backpressure, and SQL over SQLite on every platform with the same deterministic fake; opt-in, so nothing grows for apps that do not use them.

  • Objects as parameters, host callbacks (ADR-040, ADR-041)

    Generated classes cross the boundary as themselves, one wrapper per handle; the core calls back into app code through typed callback interfaces that never unwind into it.

  • Production operations (ADR-046)

    Every contained panic becomes a structured report the app receives with symbolicable frames; background runs drain the queue under a deadline; release builds keep symbols beside the binary and undra symbolicate reads them.

  • Newtypes, generics, Decimal; paged and lazy lists; polling (ADR-042, ADR-043)

    The boundary types a production app reaches for, each read as native on every platform; a lazy list pages 10,000 rows from the core on demand; polling pauses when the app does.

  • A runtime ends when its owner lets go (ADR-034)

    Tasks hold a WeakCtx; off-core writes are refused in every build (ADR-035); a panicking computed poisons only itself; stream errors are typed on the wire (ADR-036).

  • Real Android adapters

    Kv, SecureStore, Fs, Http, Connectivity and Lifecycle backed by the platform, installed with one call.

  • React Native (ADR-038)

    @undra/react-native: a TurboModule over the C ABI under the same TypeScript mirror, for teams that keep React Native for the UI.

  • Migration guides

    From Kotlin Multiplatform and from UniFFI, a cookbook of recipes, and Fieldbook, a production-shaped sample beyond the playground.

  • Several cores in one app (ADR-044)

    Each core is a self-contained image with one namespaced entry point, so two Undra libraries share a process without sharing anything, storage included.

  • iOS 15 and 16 (ADR-045)

    A lower deployment target generates ObservableObject stores and the iOS 17 output is unchanged; the mode is proven by compilation and a runtime probe on iOS 26.5, not yet on an iOS 15 or 16 runtime.

  • Generic functions, objects and stores (ADR-058)

    A function lists the types it crosses for and arrives as overloads; a generic object or store is a template, and each alias is an ordinary class with its own type id. Instantiations are declared, not open-ended; native generics, and generic queries, ports and callbacks, are not there.

  • The web call path (ADR-056)

    A generated TypeScript call went from 3.2–3.5 µs to 0.47–0.68 µs in headless Chromium, and React Native's mirror work at 100,000 updates a second from about 22 ms to about 5 ms a frame on the iPhone simulator.

  • The JavaScript runtime at 16 KB (ADR-057)

    What a hello-world page loads up front of @undra/runtime went from 22.1 KB to 15.8 KB gzipped without removing behaviour: what a page cannot run or has not asked for loads with the thing that needs it, the production build says error codes with a link where the development build says sentences, and the page that uses every feature loads less than before.

Now

Open items

owed

Built and merged, with these still open; each is a known limit that the default-choice post and the docs name too.

  • Rows from physical devices

    The device benchmarks run on the iPhone simulator, the Android emulator and headless Chromium, and are labelled so; rows from real phones are owed, and no device target is claimed as met.

  • Query handles across a dev reload

    undra dev keeps the stores across a rebuild but not query handles, which need a decision record of their own.

  • Android module tests in CI

    The undra-compose and android-adapters tests pass locally and on the emulator but do not run in CI yet.

Next

Release and reach

planned

Needs a release, an account or a decision rather than more code; the order may change.

  • The v1.0.0 release channels

    brew, npm and the curl installer go live with the first tagged release, which needs the npm organisation, the Homebrew tap and the tag, all the maintainer's to create; the pipeline is built, reviewed and proved by a green dry run.

  • crates.io and Maven Central

    Publish the crates under a registry-safe prefix (its own ADR) and the Kotlin runtime without a local build.

  • Windows CLI

    Release binaries and docs for the undra command on Windows.

  • Flutter and Dart

    Not started: decided after React Native, which has shipped.

  • A custom domain

    A home for the site and docs that is ours.

Later

Horizon

exploring

Directions under consideration, not scheduled.

  • Desktop targets

    macOS, Windows and Linux over the same C ABI.

  • A sync engine

    A separate package, not part of the core.

  • Compose Multiplatform interop

    Use an Undra core under a Compose Multiplatform UI.

Not planned

Not planned

Shared UI of any kind, and hosted services. Undra owns everything under the pixels and leaves the screens to SwiftUI, Compose, React and React Native.

How to influence the roadmap

Open an issue on GitHub and describe the problem you have rather than the feature you want; real projects and real numbers move items up. Anything that touches the wire, the runtime model, the threading model or a generated public shape needs a decision record first, and those live in .10x/adrs.
