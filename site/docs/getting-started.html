Start

Getting started

Install the toolchain, install the CLI, scaffold a project, and run it. A core you can test takes about ten minutes; the full five-language matrix takes about thirty including downloads.

Everything here was exercised end to end on an Apple-Silicon Mac, which is the reference environment. Linux paths differ only where noted in the repository's onboarding guide; Windows is untested.

What you need#

Install only what your target platforms need. undra doctor checks all of it and prints the fix for each gap.

You wantYou need
Any core (everything in crates/)Rust stable, plus the cross targets Undra ships to
WebNode 22+, and binaryen (for wasm-opt)
AndroidJDK 17, Kotlin, Gradle, the Android SDK and NDK r27, cargo-ndk
iOS (macOS only)Full Xcode from the App Store, plus an iOS simulator runtime

1. Install the toolchain#

Rust comes first, with the targets Undra builds for.

bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
rustup target add wasm32-unknown-unknown \
  aarch64-apple-ios aarch64-apple-ios-sim \
  aarch64-linux-android x86_64-linux-android

Then the platform pieces you need.

bash
# Web and the TypeScript runtime
brew install node binaryen

# Android: JDK, Kotlin, Gradle, then the SDK and NDK
brew install openjdk@17 kotlin gradle
brew install --cask android-commandlinetools
cargo install cargo-ndk

For iOS, install Xcode from the App Store (the Command Line Tools alone have no XCTest and no simulators), then:

bash
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
sudo xcodebuild -license accept
xcodebuild -downloadPlatform iOS        # simulator runtime, one time, large

The Android SDK needs a few packages (platform 35, build-tools 35, NDK 27.2, the emulator and a system image). The onboarding guide has the exact sdkmanager line and an avdmanager line that creates the undra emulator used throughout the project.

2. Install the CLI#

Pick one channel. Homebrew, the curl installer and npm put a prebuilt undra binary on your machine; cargo builds it from source with Rust 1.85 or newer. The prebuilt channels install the latest tagged release, so they work from v1.0.0 onwards; cargo builds from the repository at any time.

ChannelCommand
Homebrewbrew install shreypdev/undra/undra
npmnpm install -g @undra/cli
curlcurl -fsSL https://shreypdev.github.io/undra/install.sh | sh
cargocargo install --git https://github.com/shreypdev/undra undra-cli

The curl installer detects your OS and architecture, verifies the download against the release checksums, installs to ~/.undra/bin and prints the line to add to your PATH. It never uses sudo.

bash
undra --version
undra doctor      # prints what is missing, with the fix

undra doctor exits with status 1 when something the project needs is missing, so it works in CI too. Inside a project it only checks the platforms named in undra.toml.

From a checkout (contributors)

bash
git clone https://github.com/shreypdev/undra.git && cd undra
cargo install --path crates/undra-cli    # the `undra` command
source scripts/env.sh                   # PATH, JDK and Kotlin jars, Xcode fallback, per shell

3. Create a project#

bash
undra init myapp                        # core + SwiftUI + Compose + React shells
undra init myapp --platforms ios,web    # only some of them
undra init myapp --id dev.acme.myapp    # application id / bundle identifier
cd myapp

Nothing is downloaded: the templates are part of the undra binary. The project you get is a directory with a undra.toml and:

PathWhat it is
core/The Rust core: a working to-do store with #[undra::store] and #[undra::api]
generated/Swift, Kotlin and TypeScript bindings for that core, already generated
ios/ android/ web/One minimal, real app per platform, using the generated bindings

Pass --undra-path ~/src/undra (or set UNDRA_PATH) to use a local checkout's crates and runtimes instead of released versions.

4. Start the live loop#

bash
undra dev                          # serves the core on ws://127.0.0.1:7443
undra dev --addr 0.0.0.0:7443      # reachable from a phone on your network

undra dev runs your core on this machine and serves it over a WebSocket. A simulator, a phone or a browser tab connects with the remote transport of its runtime and uses this core instead of a built-in one. Edit Rust, save, and the core is rebuilt and restarted; the app reconnects by itself and loads the new core. Development log records (a line per transaction commit, port call and panic) print in the terminal.

No authentication. The server has none. Keep the default loopback address unless a device has to reach it, and never expose it beyond a network you trust.

5. Run each platform#

Each shell is a plain native project wired to your core, and its own README says how to run it. The short version:

Web#

bash
cd web && npm install && npm run dev

The page loads the core as a wasm module. To use the core that undra dev serves instead, load it in remote mode:

ts
await UndraCore.load({ mode: "remote", url: "ws://127.0.0.1:7443", expectedSchemaHash: UndraIds.schemaHash });

iOS#

Open ios/ in Xcode and run on a simulator. In debug builds the generated app reads UNDRA_DEV_URL (for example ws://<your Mac>:7443) and attaches to undra dev when it is set.

Debug builds of the core need the library linked with -force_load, or the linker drops the core's registrations and the schema looks empty; the generated Xcode project already does this. Release builds need no flag.

Android#

Build the core with undra build --platform android --release, then build and install from android/ with Gradle. Use --release for anything you run: a debug core is tens of megabytes per ABI. Debug builds can run against undra dev instead (no native build needed): ./gradlew -PundraDevUrl=ws://10.0.2.2:7443 :app:installDebug for an emulator, or adb reverse (undra dev --android) and ws://127.0.0.1:7443 for a USB device.

6. Build what you ship#

bash
undra build --release        # every platform in undra.toml
undra build --platform ios,android,web --release
PlatformArtifact, below build/
iOSios/UndraCore.xcframework (device and simulator slices)
Androidandroid/jniLibs/<abi>/libundra_core.so, arm64-v8a and x86_64, 16 KB page aligned
Webweb/undra_core.wasm, release profile then wasm-opt -Oz
Hosthost/libundra_core.{dylib,so}, for JVM tests and undra bindgen

Sizes are printed at the end next to the design's budgets. On the reference build the hello-world web core is 135 KB (currently over the 120 KB budget; tracked as E5) gzipped and an Android .so is 831 KB per ABI.

Prefer to explore first?#

Try it in your browser first: the live playground is the real Rust core running as WebAssembly. The playground source is the same thing, fully built: a to-do list, a counter, a 10,000-row keyed list and remote queries with an offline switch, on Chrome, an iPhone simulator and an Android emulator. It uses only public APIs, and proof screenshots are committed in its .proof/ folder.

bash
undra build -C examples/playground --platform web
cd examples/playground/web && npm install && npm run dev

If you are contributing#

Every suite runs locally and nothing needs the network after install. The table is the same one the CI matrix follows.

SuiteCommand
Rust workspacecargo test --workspace
Lintscargo fmt --check && cargo clippy --workspace --all-targets -- -D warnings
TypeScript runtimecd runtimes/ts/@undra/runtime && npm ci && npm test
Kotlin runtimeruntimes/kotlin/undra-runtime/scripts/test-local.sh
Swift runtimecd runtimes/swift/UndraRuntime && swift test
wasm ABIbash crates/undra-ffi/tests/wasm/run.sh
Contract scenarios, three platformsbash contract-tests/run-all.sh
Benchmark budget gatecargo test -p undra-bench --test budgets --release

Read CLAUDE.md (the constitution) and docs/SPEC.md before you write code; the architecture page digests the rules. Changes land one piece per worktree, with an adversarial review before merge; docs/AGENT_WORKFLOW.md describes the loop for humans and agents alike.
