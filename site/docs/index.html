Undra documentation

Undra owns the part of your app that is not pixels: domain logic, reactive state, the data layer, persistence and the dev loop. These pages take you from an empty directory to a running app, then explain how the pieces work.

Where to start#

  • New here? Getting started installs the toolchain and CLI, scaffolds a project, runs the live dev loop and puts an app on each platform.
  • Writing a core? Core concepts covers stores, signals, computeds and keyed lists. Queries & mutations covers the data layer, and Ports & adapters covers everything that touches the outside world.
  • Looking something up? The CLI lists every command and flag. Architecture explains the schema, the generators, the wire and the twelve rules. The API overviews show what a record, error, store or port looks like in Swift, Kotlin and TypeScript.

The idea in four sentences#

You write your domain in Rust and mark it with a handful of attributes. Undra generates idiomatic Swift, Kotlin and TypeScript from the schema those attributes produce, so the UI stays SwiftUI, Compose and React. Each platform keeps a local mirror of your state, so reads never cross the language boundary. A write crosses once per transaction, and the core answers with one compact binary change-set that patches every mirror.

Where these pages come from. Everything here is digested from the repository: the README, the specification in docs/SPEC.md, the onboarding guide, the benchmark results and the playground app. When a page and the spec disagree, the spec wins; the repository is the record.

A note on numbers#

Performance figures on this site are host-measured (an Apple M5 Pro, release builds) and guarded by budgets in CI. They are not device numbers. The design's per-device targets (an iPhone, a mid-range Android phone, Chromium) are tracked in bench/RESULTS.md, and nothing on this site claims them as measured.
