API overview

API overview, TypeScript

Generated TypeScript is strict-mode ESM with no any in exported types: plain interfaces and unions for data, promises for calls, signals for state, and hooks for React. The core package has no runtime dependencies.

keel bindgen writes an npm package (src/*.ts, package.json, tsconfig.json) that imports only from @keel/runtime. The shapes below come from the playground's generated code and the specification (§10.3).

Loading the core#

Load the core once, before you create a store. The runtime compares the core's schema hash with the one the bindings were generated from and rejects a mismatch with KeelSchemaMismatch.

web/src/keel.ts
import { KeelCore } from "@keel/runtime";
import { KeelIds, Todos } from "@playground/core";
import wasmUrl from "../../build/web/keel_core.wasm?url";

await KeelCore.load({
  mode: "wasm-main",                       // the core runs in a wasm module on this thread
  wasm: new URL(wasmUrl, location.href),
  expectedSchemaHash: KeelIds.schemaHash,
  adapters: { http, kv },                  // optional: replace a default adapter
});

const todos = await Todos.create();        // uses KeelCore.shared
modeWhere the core runs
"wasm-main"a wasm module on the page's main thread
"wasm-worker"the same module in a worker, keeping the main thread free
"remote"the core that keel dev serves, over a WebSocket: { mode: "remote", url: "ws://127.0.0.1:7443", expectedSchemaHash }

64-bit integers become bigint so no value is ever silently rounded; a 64-bit value outside the safe range is a decode error rather than a wrong number when you opt into number.

Records and enums#

ts
/** One item of the to-do list. */
export interface Todo { id: string; title: string; done: boolean }

export type Filter = "all" | "active" | "done";

export type Figure =
  | { kind: "circle"; radius: number }
  | { kind: "rect"; width: number; height: number }
  | { kind: "label"; value: string }
  | { kind: "empty" };

A switch (figure.kind) over the union is exhaustive under strict, so adding a variant in Rust breaks every switch that forgot it.

Errors#

A #[keel::error] becomes an abstract class with a kind and one subclass per variant, so you can branch with instanceof or on kind. A rejected call carries the typed error, not a string to parse.

ts
export abstract class TodoError extends KeelError {
  readonly kind: "emptyTitle";
}
export namespace TodoError {
  export class EmptyTitle extends TodoError { /* message: "the title cannot be empty" */ }
}

try {
  await todos.add(draft);
} catch (error) {
  if (error instanceof TodoError) setProblem(error.message);
}

Objects and functions#

An object is a class holding a handle. Every method returns a Promise, which keeps the API uniform across main-thread, worker and remote modes. Stream methods return an AsyncIterable, and any call takes an optional AbortSignal as its last argument to cancel it in the core.

ts
export class Probe extends KeelObject {
  static create(core?: KeelCore): Promise<Probe>;
  counters(): Promise<ProbeCounters>;
  wait(ms: number, signal?: AbortSignal): Promise<number>;
  ticks(count: number): AsyncIterable<number>;     // backpressure through stream credit
}

export function add(a: number, b: number): Promise<number>;

Release an object with close() (idempotent) or with using where Symbol.dispose exists (Node 20+ and current browsers); a FinalizationRegistry is the backstop.

Stores and signals#

A store extends KeelStore. Every signal is a read-only Signal<T>: get() returns the current value, peek() reads without subscribing, and subscribe(fn) calls you on change and returns an unsubscribe function. Computed signals are written by the core.

ts
export class Todos extends KeelStore {
  readonly todos: Signal<Todo[]>;
  readonly filter: Signal<Filter>;
  readonly visible: Signal<Todo[]>;        // computed by the core
  readonly remaining: Signal<number>;      // computed by the core

  static create(core?: KeelCore): Promise<Todos>;
  setFilter(f: Filter): Promise<void>;
  add(title: string, signal?: AbortSignal): Promise<Todo>;
}

Change-sets are batched with queueMicrotask into one flush per macrotask, so several signals that changed in one transaction update together and a component never renders a half-applied state.

React and the other frameworks#

@keel/runtime/react exports two hooks. useSignal is useSyncExternalStore over a signal, with a server snapshot. useKeel creates a store when the component mounts and closes it when it unmounts; it returns undefined until the store exists, and useSignal accepts an undefined signal.

tsx
import { useKeel, useSignal } from "@keel/runtime/react";

export function CounterView() {
  const counter = useKeel(Counter);            // undefined until created
  const count = useSignal(counter?.count);
  const parity = useSignal(counter?.parity);   // computed in the core, same change-set
  if (counter === undefined) return null;
  return <button onClick={() => void counter.increment()}>{count} ({parity})</button>;
}

Adapters ship for the other frameworks as thin files, exported from @keel/runtime/vue (useSignal as a shallowRef, useKeel), /svelte (signalStore, a Readable) and /solid (useSignal as an Accessor, useKeel). The frameworks are optional peer dependencies; the core package imports none of them.

Query handles#

A #[keel::query] becomes a store with five signals (data, status, error, fetching, updatedAt) plus refetch() and invalidate().

ts
const inbox = await RemoteTodosQueryHandle.create("inbox");
const items = useSignal(inbox.data);        // RemoteTodo[] | null
const busy = useSignal(inbox.fetching);
await inbox.refetch();

See Queries & mutations.

Ports#

The ten standard ports and their types are exported from @keel/runtime and are not generated into your package. The browser defaults use fetch, IndexedDB, OPFS, setTimeout, navigator.onLine and visibilitychange; Node uses fetch and files. Replace one with adapters in KeelCore.load. A port you define yourself becomes an interface:

ts
export interface Http extends KeelPort {
  request(req: HttpRequest): Promise<HttpResponse>;
}

See Ports & adapters.

Testing#

The runtime is testable without a browser: over the remote transport against a native core, and against a WAT stub of the wasm ABI. The contract suite runs the same scenarios as the Swift and Kotlin runners, against the real wasm module.
