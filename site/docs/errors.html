Error codes

Every diagnostic Undra raises, from a macro at compile time, from schema validation, from the runtime or from the undra command, has a stable code, a fixed shape and a fix. The link at the end of each message lands on its code below.

How to read one

A diagnostic says what is wrong, why the rule exists and how to fix it. This one is verbatim from the macro test suite:

text
error[undra::E0004]: trait object `dyn Fn(u32)` cannot cross the boundary
  = note: trait objects have no wire representation and no equivalent in Swift, Kotlin or TypeScript
  = help: use a concrete `#[undra::api]` type or an enum listing the cases you need; callbacks into the platform are ports (`#[undra::port]`)
  = docs: https://shreypdev.github.io/undra/docs/errors.html#E0004

Types and shapes#

E0001 unsupported type in a public position#

Raised by macros, schema validation, the Encode/Decode bounds.

unsupported type in a public position (lists the type and the allowed set); includes Lazy<T> (lazy lists are not available in v1), a DerivedList field without its row type (ADR-039), Handle (no schema type; objects cross through constructors), a Result whose error type is not a #[undra::error] enum, a Ctx parameter that is misplaced (on a method, not first, or &mut), and a type used as a value that cannot cross (an Encode/Decode bound that is not met: a struct without #[undra::api])

What you seeWhyFix
Plain cannot cross the boundary by valuea value crosses as a scalar, String, Bytes, Vec, Option, a map, Duration, Timestamp, Uuid, or a type declared with #[undra::api] (records, enums) or #[undra::error]; an object (#[undra::api] impl) crosses by handle, never as a valuedeclare Plain with #[undra::api], or return a record with the data the platform needs
DerivedList needs the type of its rowsa derived list is a Vec of rows the platforms mirror, so the schema needs the row type, written as the one type argumentwrite DerivedList<Row> for visible, with the type the pipeline's build() produces
Lazy<Row> is not available in v1: lazy lists cannot be mirrored yeta Lazy<T> signal is a list the platform pages through on demand; the platform runtimes have no API for it yet (SPEC section 17), so no language could observe itexpose the items as a Signal<Vec<T>> (keyed with #[undra(key = "..")] if they have an id) or as a paged method that takes an offset and a limit
&str cannot cross the boundaryreferences have no wire representation; every value crosses by copyuse an owned String
usize cannot cross the boundaryits width differs between platforms (32-bit wasm, 64-bit iOS and Android), so the wire layout would toouse a fixed-width integer such as u32 or u64
Ctx parameter on method touchmethods reach the runtime through the object: Ctx is only injected into constructors, free functions, queries and mutationskeep a WeakCtx (ctx.downgrade()) in the object when it is constructed and upgrade it in the method, or use Ctx::current()

E0022 non-Send future in an async method: rustc's own error, pointed at the method by an assertion named after this code#

Raised by rustc, named by a macro.

non-Send future in an async method or query: rustc's own "future cannot be sent between threads safely", pointed at the method by an assertion the macros emit; the last note names the assertion, _undra_error_E0022_the_future_of_an_async_method_must_be_Send. Do not hold a non-Send value (an Rc, a RefCell borrow, a MutexGuard) across an .await

The compiler reports this one itself, so it carries no Undra code. It is pointed at the method, and the last note names the assertion the macro emitted, _undra_error_E0022_the_future_of_an_async_method_must_be_Send: the code to look up.
