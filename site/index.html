Rust core · native UI

One Rust core. Native everywhere.

Write your domain once in Rust. Keel generates the Swift, Kotlin and TypeScript your engineers would have written by hand, and your UI stays SwiftUI, Compose and React.

Architecture · live
  • 1 reads never cross: each UI reads its local mirror
  • 2 one crossing per transaction
  • 3 binary change-sets, fanned out to every mirror
  1. WriteOne call crosses the boundary, once per transaction.
  2. CommitThe core commits and builds one binary change-set.
  3. ApplyEvery mirror patches itself. Every read stays local.

Quick start

60 seconds to a native app

Scaffold a project, start the live core, open a shell. The templates ship inside the binary, so nothing is downloaded and the bindings are already generated.

  1. keel init myappA Rust core with a working to-do store, plus SwiftUI, Compose and React shells.
  2. keel devServes the core over a WebSocket and rebuilds on save. Edit Rust, reload the app.
  3. Open a shellEach shell is a plain native project that uses the generated bindings.

How it works

Describe once. Generate native. Write once per change.

The schema is the only source of truth. keel bindgen reads it and writes Swift, Kotlin and TypeScript with no wrappers, no reflection and no Any. Golden files lock the output.

core/src/todos.rs
#[keel::api]
pub struct Todo {
    pub id: Uuid,
    pub title: String,
    pub done: bool,
}

#[keel::store]
pub struct Todos {
    #[keel(key = "id")]
    todos: Signal<Vec<Todo>>,
    visible: Computed<Vec<Todo>>,
    remaining: Computed<u32>,
}

#[keel::api(store)]
impl Todos {
    pub async fn add(&self, title: String)
        -> Result<Todo, TodoError> { /* … */ }
}
TodosScreen.swift
struct TodosScreen: View {
  let todos: Todos  // @Observable

  var body: some View {
    List(todos.visible, id: \.id) { todo in
      Text(todo.title)
    }
    .toolbar {
      Text("\(todos.remaining) left")

  }
}

// async throws(TodoError)
try await todos.add(title: draft)

SwiftUI. @MainActor @Observable stores and typed throws.

TodosScreen.kt
@Composable
fun TodosScreen(store: Todos) {
  val visible by store.visible
    .collectAsState()
  val remaining by store.remaining
    .collectAsState()

  Text("$remaining left")
  LazyColumn {
    items(visible, key = { it.id }) {
      Text(it.title)
    }
  }
}
// suspend fun, throws TodoError
store.add(draft)

Compose. Signals are StateFlows; add is a suspend fun.

TodosView.tsx
export function TodosView() {
  const store = useKeel(Todos);
  const todos = useSignal(store?.visible);
  const left = useSignal(store?.remaining);

  return (
    <>
      <h2>{left} left</h2>
      {todos?.map((t) => (
        <li key={t.id}>{t.title}</li>
      ))}
    </>
  );
}
// Promise, rejects with TodoError
await store?.add(draft);

React. useSignal is useSyncExternalStore over the mirror.

What's in v1

Everything under the pixels, in one place.

Stores, signals and computeds

A store is an object with reactive fields. Signals hold state, computeds derive from it, and a transaction batches writes into one change-set. Only signals a platform observes are sent.

counter.rs
pub fn add(&self, amount: i32) {
    self.ctx.txn(|| {
        self.count.update(|c| *c = c.saturating_add(amount));
        self.changes.update(|n| *n = n.saturating_add(1));
    });   // one transaction, one change-set
}

Queries and mutations

#[keel::query] gives you a cache with staleness, dedup, retry and persistence. Optimistic updates roll back precisely: only what the failed mutation wrote is restored.
