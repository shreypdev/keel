One Rust core. Native everywhere.

Keel owns everything under the pixels of your iOS, Android and web apps: domain logic, reactive state, the data layer, persistence and the dev loop. The UI stays 100% native: SwiftUI, Jetpack Compose and React, written by hand.

It is the opposite of a cross-platform UI framework. Your screens never leave the platform. Your logic stops being written three times.

  • 3 binary change-sets, fanned out to every mirror

  2. CommitThe core commits and builds one binary change-set.
  3. ApplyEvery mirror patches itself. Every read stays local.

A list write costs the change, not the list.

Recording the list operation instead of rediscovering it took a one-row insert into a 10,000-row observed list from 536 µs to 6.3 µs. A keyed patch is now O(change). ADR-027 has the before and after.

How to read this. Medians from cargo bench (criterion, release, LTO) on an Apple M5 Pro. "Target" is the design's per-device budget; a phone core is slower than this host, so a pass here is necessary, not sufficient. "CI gate" is the regression guard in bench/budgets.toml, about 5x the host median; it fails the build. The two size rows are recorded when the core is built. Device-measured numbers (iPhone, mid-range Android, Chromium) are tracked in RESULTS.md and are not claimed here.

How it works

Describe once. Generate native. Write once per change.

1

Describe it in Rust

Mark your types and functions. The macros emit a schema, and the schema is the only source of truth: nothing public exists that it cannot describe.

rust
#[keel::api]
pub struct Todo {
    pub id: Uuid,
    pub title: String,
    pub done: bool,
}
2

Generate native code

keel bindgen reads the schema and writes Swift, Kotlin and TypeScript. No wrappers, no reflection, no Any. Golden files lock the output.

  • $ keel bindgen
  • + generated/swift/…/Stores.swift
  • + generated/kotlin/…/Stores.kt
  • + generated/ts/src/stores.ts
3

Read locally, write once

Each platform holds a mirror of your state. A write crosses once; the change-set updates every signal it touched in a single main-thread apply.

store.add("milk") crosses once
↓
change-set todos · visible · remaining
↓
mirrors patched, reads stay local
What it looks like

Write it once in Rust. Read it natively.

The shapes below come from the README and from examples/playground, which runs one core on Chrome, an iPhone simulator and an Android emulator.

Rust core

core/src/todos.rs
use keel::prelude::*;

/// One item of the to-do list.
#[keel::api]
pub struct Todo {
    pub id: Uuid,
    pub title: String,
    pub done: bool,
}

/// Why an item could not be added.
#[keel::error]
pub enum TodoError {
    #[error("the title cannot be empty")]
    EmptyTitle,
}

/// The to-do list: what every UI observes and calls.
#[keel::store]
pub struct Todos {
    #[keel(key = "id")]
    todos: Signal<Vec<Todo>>,
    filter: Signal<Filter>,
    visible: Computed<Vec<Todo>>,
    remaining: Computed<u32>,
}

#[keel::api(store)]
impl Todos {
    pub async fn add(&self, title: String) -> Result<Todo, TodoError> { /* … */ }
    pub fn set_filter(&self, filter: Filter) { /* … */ }
}

One definition. visible and remaining are computed in the core and arrive in the same change-set as the write that caused them.

SwiftUI

TodosScreen.swift
// SwiftUI: Todos is @Observable. Reading a signal is a plain property read.
struct TodosScreen: View {
    let todos: Todos            // try Todos(ctx: .shared)
    @State private var draft = ""
    @State private var problem: String?

    var body: some View {
        List {
            ForEach(todos.visible, id: \.id) { todo in
                Button { todos.toggle(id: todo.id) } label: {
                    Label(todo.title, systemImage: todo.done ? "checkmark.circle.fill" : "circle")
                }
            }
        }
        .toolbar {
            ToolbarItem(placement: .principal) { Text("\(todos.remaining) left") }
        }
    }

    private func add() {
        Task {
            do { _ = try await todos.add(title: draft); draft = "" }
            catch { problem = error.localizedDescription }   // TodoError.emptyTitle
        }
    }
}

No wrappers. add(title:) is async throws(TodoError); the store is @MainActor @Observable.

Compose

TodosScreen.kt
// Compose: signals are StateFlows.
@Composable
fun TodosScreen(vm: TodosViewModel = viewModel()) {
    val store = vm.store
    val visible by store.visible.collectAsState()
    val remaining by store.remaining.collectAsState()

    Column {
        Text("$remaining left")
        LazyColumn {
            // keyed by id in the core, so Compose moves rows instead of redrawing them
            items(visible, key = { it.id }) { todo ->
                TodoRow(todo, onToggle = { store.toggle(todo.id) })
            }
        }
    }
}

// in the ViewModel
viewModelScope.launch {
    try { store.add(draft) }
    catch (e: TodoError) { /* TodoError.EmptyTitle */ }
}

No extra module. collectAsState() on the store's StateFlows; add is a suspend fun that throws the typed error.

React

TodosView.tsx
// React: hooks from @keel/runtime/react (vue, svelte and solid adapters ship too).
import { useKeel, useSignal } from "@keel/runtime/react";
import { Todos, TodoError } from "@playground/core";

export function TodosView() {
  const store = useKeel(Todos);            // undefined until it exists
  const todos = useSignal(store?.visible);
  const remaining = useSignal(store?.remaining);

  async function add(title: string) {
    try {
      await store?.add(title);
    } catch (error) {
      if (error instanceof TodoError) { /* a typed error, not a string to parse */ }
    }
  }
  /* … render todos, `${remaining} left` … */
}

Hooks, not glue. useSignal is useSyncExternalStore over the mirror; useKeel creates the store on mount and closes it on unmount.

Queries

core/src/remote.rs
/// The items of a server list, cached per list, fresh for 30 s, persisted.
#[keel::query(key = "remote-todos:{list}", stale = "30s", persist, retry = 1)]
pub async fn remote_todos(ctx: &Ctx, list: String) -> Result<Vec<RemoteTodo>, RemoteError> {
    let url = endpoint(ctx, &format!("/lists/{list}/todos"))?;
    parse(&send(ctx, HttpRequest::get(url)).await?)
}

/// Shows the item at once; takes it back if the server refuses.
#[keel::api]
pub async fn create_remote_todo(ctx: &Ctx, list: String, title: String) -> Result<RemoteTodo, RemoteError> {
    // …build `placeholder`…
    ctx.mutate::<PostRemoteTodoMutation>((list, title))
        .optimistic(move |cache| {
            cache.update::<RemoteTodosQuery>((cached,), |items| items.push(placeholder));
        })
        .await
}

The data layer is in the core. Staleness, dedup, retry with jitter, optimistic updates with surgical rollback and an offline queue replayed on reconnect.

Stores, signals and computeds

A store is an object with reactive fields. Signals hold state, computeds derive from it, and a transaction batches writes into one change-set. Only signals a platform observes are sent.

counter.rs
pub fn add(&self, amount: i32) {
    self.ctx.txn(|| {
        self.count.update(|c| *c = c.saturating_add(amount));
        self.changes.update(|n| *n = n.saturating_add(1));
    });   // one transaction, one change-set, `parity` included
}

Queries, mutations and offline

#[keel::query] and #[keel::mutation] give you a cache with staleness, dedup, retry, persistence and an offline queue. Optimistic updates roll back precisely: only what the failed mutation wrote is restored.

rust
ctx.mutate::<PostRemoteTodoMutation>((list, title))
    .optimistic(|cache| { /* show it now */ })
    .await   // refused? the optimistic write is undone

Keyed lists, O(change)

Insert, remove, update and move cross as one-operation patches, however long the list is. On a 10,000-row list: 6.3 µs to insert, 272 ns to update, 9.7 µs to move.

Principles

Twelve rules, enforced in review.

The constitution every change is held to, human or agent. Read the digest or the source, CLAUDE.md.

R1
The schema is the only truthA public type exists only if the schema can describe it. Every language's output derives from it.
R2
unsafe has one homeOnly keel-ffi (plus one schema loader in the CLI). Every block carries a SAFETY comment; every other crate forbids it.
R3
Generated code passes native reviewA Swift, Kotlin or TypeScript engineer who never saw Rust would write it that way. Golden files lock it.
R4
Every feature lands wholeUnit tests, contract scenarios, a benchmark if the boundary moves, docs on every pub item.
R5
Reads never cross the boundaryWrites cross once per transaction. No generated getter calls into the core.
R6
Nothing escapes as a panicEvery boundary entry is guarded and every error is a typed value.
R7
Compatibility is checkedSchema hash at load and at build. Breaking the wire is a major version and an ADR.
R8
Macro errors teachCode, what, why, fix, docs link.
R9
Budgets are testsBenchmarks live in bench/; a regression fails CI.
R10
We ship on it firstexamples/playground uses only public APIs.
R11
Boundary changes need an ADRWire, runtime model, threading or a generated shape: decision record before code.
R12
The core is deterministicNo wall clock, randomness or threads outside the Clock, Rng and Timer ports and the runtime.
